# 固定输入与验收

将源码快照、交付目录和技能放在独立目录。已有平台快照可直接使用其 `files` 清单。对已经准备好的独立源码目录，也可运行下列命令。清单只记录文件名与 SHA-256，保存在源码目录外。二进制资源可保留在快照中，但不能当作源码行引用。

```sh
python <skill>/scripts/check_dossier.py manifest --source <fixed-source> --out <manifest.json>
python <skill>/scripts/check_dossier.py check --source <fixed-source> --manifest <manifest.json> --book <dossier-root>
```

在交付目录中保存 `coverage.json`。以下是格式示例，字段值由当前项目替换。入口匹配使用对快照相对路径的 shell 通配。每个匹配文件需有主责模块或有理由的排除处置；可追加非匹配入口。每个模块文档以反引号引用真实的 `相对路径:开始行-结束行`。功能 ID 放在其对应段落。原型状态使用 HTML 元素 id；无界面的命令或协议原型可以用 Markdown 中显式标出的状态标识。

```json
{
  "inventoryPatterns": ["src/routes/*.ts"],
  "surfaces": [{"path":"src/routes/order.ts","module":"ORD"}],
  "modules": [{"id":"ORD","document":"orders.md","features":["ORD-SUBMIT"]}],
  "artifacts": ["design.md","interfaces.md","operations.md"],
  "journeys": [{
    "id":"submit-order","features":["ORD-SUBMIT"],
    "prototype":"prototype.html","states":["draft","rejected"],
    "acceptance":"acceptance.md","case":"AC-ORDER-1"
  }]
}
```

排除项写为 `{"path":"...","excluded":"具体原因"}`。每个关键操作旅程至少声明一次验收与状态。所有面向使用者的核心功能应有对应的旅程或在覆盖报告中具体说明其验收方式；外围/后台功能可在模块内提供 API、日志或状态断言。已有的历史稿不要登记为新版本的源码证据。

校验器检查清单文件哈希、入口归属、文档及功能 ID、所有声明的原型状态、验收编号和源码引用范围。结果显示被检查的数量；失败以非零码退出。它不判断规则含义、不运行原型，也不证明清点的边界完整。交付时还要给出独立语义评审、真实的原型操作记录，以及每项覆盖或未覆盖的说明。

只有部署或包身份意义的文件可作为证据保留；若纳入入口匹配但没有可调用功能，在 surfaces 写明排除理由。独立评审记录放在交付目录的 verification.md 或等价报告，列出抽到的操作、证据、修订和仍待验证事项。

## 语义证据与受阻恢复

- **保留原始依据。** 选证据和压缩摘要时，保留固定源码的原始路径、范围与指纹，包括配置、类型定义和测试。索引中的函数 ID 是导航入口，不能替代这些引用；未收录进函数索引的文件仍可构成有效证据。
- **按陈述组织取证。** 完整原始引用作为审计保留，单次核验只取当前陈述对应的完整操作、必要守卫和相关补充资料，不把整个模块的资料复制给每一句。细粒度操作未被索引时，可以从包含它的最小完整工厂定位，再复核正文。证据包仍超预算时报告缺口或拆分陈述，并保留原文明示的共同条件；不能切散必要守卫后以任意一页的支持代替整条结论的核验。
- **先补检，再改写。** 原引用中没有被调用函数时，可有界地沿当前快照已验证的原生调用关系找完整定义，保留原引用、调用路径与新增位置的指纹。静态调用关系只帮助导航，不证明动态执行或授权成立；无法展开的边界仍须明确记录。新一轮实际选择的来源未变时，复用原核验记录，另存本次探索，不仅因目录扩大就重复核验。
- **核对同一个命题。** 按原陈述的主体、适用范围、条件、结果与副作用审阅；“每次”“所有”等范围须覆盖相应分支，包括提前返回、幂等处理和回退路径。保留同一操作原段落已经明确的前提，避免把断句后的分支误读为无条件保证；不能从后文或无关操作借用条件。证据只支持有条件的行为时，把条件写回陈述再评审，不能只在评审理由中补条件而认可原来的无条件陈述。
- **逐项检查对应关系。** 并列赋值逐一核对每个目标与右值，分别核对参数位置、返回值及事务内外的边界。评审理由即使正确复述了代码，也不能据此认可与代码不同的原句。用真实反例与准确对照检查评审方法，机械测试通过不代表生成内容准确。
- **区分证据强度。** 文档、配置、类型和测试定义可以支持设计或实现约束，不能单独证明实际执行、测试通过或部署后的结果。缺少支持属于未证实，只有相反证据才构成矛盾；当前摘要或选取结果不足，不等于固定原文没有证据。
- **恢复真实内容。** 受阻时对照完整的固定原文，指出选取或摘要具体丢失了什么，再定向补取并重写有依据、范围准确的摘要。将来源性质、取证限制和未决事项放入验证记录，与项目业务事实及已发现的不准确陈述分开；不要用占位描述补齐条目数后声称语料完整。无法恢复的内容明确报告缺口，保留已核实部分供复验。
- **跨轮保留修正见证。** 原字段修正后，下一轮检索继续保留修正时实际提供且经校验的完整见证，以固定快照、原字段与正文指纹、修正文句指纹以及来源路径、范围和指纹绑定。只有属于该字段的见证才能继续作为检索锚点，不能退回旧窄目录而再次丢失已有源码，也不能跨字段借用。锚点只是候选来源，新陈述仍须按原规则核验。
- **保留矛盾并限定重试。** 补检只替换确实变化的证据不足项；已发现的矛盾及见证保留到有依据的正文修订之后，不能通过重新采样或退回“未知”消除阻断。对同类失败先做小范围对照，记录实际调用上限与停止条件；反复发生上游错误时，用已成功过的请求区分服务故障与新格式问题，保留失败记录，不启动整仓重跑或宣称语义通过。
- **传输受阻时交接执行。** 有界重试后仍无进展时，保留已验证结果，把未完成工作按固定快照、陈述或字段身份及完整必要源码拆成精确数据包，交给当前环境可用的原生或成员 harness Agent。返回结果仍走原有身份、敏感输出及响应解码检查，通过前不记成功；记录实际执行 Agent、请求与输出指纹及混合来源，不把原生输出标成此前模型的结果，兼容响应封装也不等于真实 HTTP 请求或已知用量。导航响应通过只说明格式、身份和定位可用，不表示语义成立；局部核验或修正通过也不表示整仓候选合格。交接仍须限定尝试次数，无进展时保留缺口并结束该波。本轮采用的是私有适配交接，不代表平台已发布自动切换能力；使用前先确认当前环境确有可用的执行和校验接口，不虚构工具或脚本。
