# 连续会话中的记忆更新、隔离与一次性许可

2026-11-10 · TeamSynergy 原生记忆切片

本轮在同一聊天中完成了重复读取、共识替换、项目切换、一次性动作许可与回滚记录的真实模型验证。回答模型通过本机 Magpie 调用 DeepSeek V4.1 Flash，两个条件均使用真实 TencentDB Wiki/Core 与 OpenViking。对照变量是是否省略已读且未变化的正文，不是关闭或开启双引擎。

## 实际改变

1. MCP 增加显式会话回执 `context_receipt`。不带回执时返回全文；继续读取会重验旧来源，未变化返回引用，变化返回当前正文，撤回或失权返回失效编码。`read_memory_source` 可强制重读原文。回执只保存来源指纹，在进程内保留 30 分钟，最多 128 条、每条 40 个来源。
2. 设备认证 API 增加 `POST /projects/:projectCode/memory/sources`，复用现有领域权限、账号归属、项目范围与原生撤回规则。新接口不接受调用者指定其他账号，不从远端索引直接信任旧正文。
3. 新增供可信 harness 适配器使用的一次性动作 ledger，绑定账号、项目、会话、仓库、远端、分支与提交。执行前先消耗；失败、过期、撤销、重放及目标变化均不会恢复次数。模型工具没有创建许可的能力。
4. 修复实际实验暴露的读取缺陷：已决定议题的后续记录原本会被简报隐藏。在异步索引尚未更新时，模型既拿不到新简报，也无法通过语义索引发现它。现在同一当前需求修订中、晚于最后有效决定的讨论记录可进入简报，保留 `discussed`，原决定保留 `confirmed`。决定前旧方案、撤回、归档与旧修订继续过滤。

第 4 项没有新增“事实已验证”的状态，也没有把记录里的部署声明当作平台执行证明。当前模型能区分原文描述的演练事实与决定，但正式执行证据、环境对象和可验证的部署事件仍需要产品化。

## 试验条件与独立核验

最终有效运行见 [result.attempt4.json](experiments/memory-harness-pilot/lifecycle/result.attempt4.json)。2026-11-10 15:16:20–15:18:42 UTC，共两场独立聊天，每场 10 轮。使用 DSH **0.2.1-rc.2 sdk-minimal**，每场复用同一个进程、Agent history 和 `sessionId`，不是重复创建空白会话。关闭自动压缩、文件、shell 与其他非必要能力。工作区路径为无条件标签的随机值，两组工具、系统提示和输入相同。

| 对照条件 | 实际读路径 |
| --- | --- |
| full | 相同 MCP 协议和回执，每次返回完整正文 |
| delta | 相同 MCP 协议和回执，已读同版本返回引用 |

两组均连接真实双引擎。模型搜索的 HTTP 观察显示项目请求为 `engine-and-platform`，引擎为 `wiki,core`，本人请求为 `engine-and-platform`，引擎为 `viking`；相关来源确实出现在相应命中渠道。本轮项目问题有字面与引擎重叠，不能据此声称语义召回相对字面检索提高了多少。

原文投影、向量存储、账号交叉拒绝由复用的真实引擎夹具核验。后续共识和环境记录立即写入隔离 PG，故意保留旧远端索引，检验旧索引仍命中时的当前来源过滤，以及新条目未索引时的可见性。平台更新通过真实 application capture 与认证撤回 API 完成，模型本轮只暴露读取与模拟动作工具；本试验不证明 Agent 会自动提炼整个聊天并写回。

[Magpie 网关审计](experiments/memory-harness-pilot/lifecycle/magpie-audit.attempt4.json)确认 **42/42** 响应来自指定模型路由，全部 HTTP 200，无传输失败或目录条件泄漏。另从 Magpie 自身 usage 按相同 UTC 时间窗、路由和端点独立核对：[usage 汇总](experiments/memory-harness-pilot/lifecycle/provider-usage.attempt4.json)含 42 个不同 response ID，`served_model=deepseek-v4.1-flash`，`swapped=false`。聚合计数为 input 12,604、cache-read 196,608、output 5,332 token；不包含账号、密钥、原始请求或逐条 usage。该数据没有逐组归属，不能用来计算分组 token 节省率。

原始网关审计的 `variants=off,on` 是继承旧 runner 的元数据错误，已在 [运行索引](experiments/memory-harness-pilot/lifecycle/run-index.json)中说明，原审计保留。runner 的两组都指向启用引擎的 API，正式结果明确 `fullAndDeltaAreBothDualEngine=true`；wrapper 源码已修正后续标签为 `full,delta`。

## 四类场景的实际结果

| 场景 | full / delta 最终结果 | 证据边界 |
| --- | --- | --- |
| 同聊天共识更新 | 均从讨论中的 5 秒更新为已确认 8 秒，`implemented=false`；引用新来源，不引用撤回来源，工具报告旧来源失效 | 操作者侧更新后明确要求重读；未验证任意后台更新的自主感知 |
| 跨项目隔离 | 同一账号有两项目权限，旧连接切换后返回 `memory_binding_changed`；模型均解释需重启。新观察连接只读到新项目独立 13 秒来源，账号通用中文提交偏好仍可用 | 重启正例由独立 MCP 观察进程完成，原模型聊天未同会话重接，旧聊天原文没有被删除 |
| 一次性推送许可 | 无许可时各组模拟效果为 0；宿主给出确定许可后各执行 1 次；模型实际重试同令牌均收到 `memory_authorization_used`，效果仍为 1 | `fake_push` 仅记日志；未执行 Git，也未接管成员原生 shell |
| 回滚记录 | 均识别曾发布 v2、当前回到 v1，引用当前回滚来源；撤回的旧“当前 v2”来源不再返回 | 发布、回滚是注入的隔离演练记录，没有执行部署或真实回滚 |

确定性授权测试还独立覆盖到期、主动撤销、账号／项目／会话／目标变化、并发消费、失败后重试、适配器重启、确认事件重放与容量边界。这里的宿主确认事件是测试控制通道提供的，不是模型判断一句话就能自行生成。

## 上下文开销与重复取证

下表计量的是 MCP 返回的所有文本字符，包含正文和回执元数据，不等于完整模型输入 token 或费用。

| 回合 | full 字符 | delta 字符 |
| --- | ---: | ---: |
| 首次读取 | 2,160 | 2,160 |
| 同题再次核验 | 1,045 | 294 |
| 项目／本人分流搜索 | 1,319 | 568 |
| 共识更新 | 438 | 798 |
| 发布记录 | 855 | 766 |
| 回滚记录 | 733 | 666 |
| 无许可推送请求中的记忆读取 | 915 | 146 |
| 绑定切换拒绝 | 42 | 42 |
| **整场合计** | **7,507** | **5,440** |

受控重复回合总返回减少 **71.9%**，来源引用保持正确。该回合正文为 901→2 字符，元数据却为 144→292 字符，因此不能把正文节约率当成总开销节约率。背景样本包含人为重复的长验证说明，适合验证重复正文抑制，不能据此预测一般项目的平均收益。

整场工具返回少 **27.5%**，两组各调用工具 14 次。两组初次都选择了简报加搜索，未携带回执，仍有重复；delta 在共识更新后主动按来源重读了一次全文，导致该回合开销高于 full。回执解决了重复正文传输，没有消除所有重复取证或保证模型采用最少工具。普通首次读取没有新增来源重验请求，后续回执读取会增加当前权限与来源重验的 HTTP／数据库开销。

这是单次配对结果，不是统计显著的性能结论。固定读取回合与整场随机工具选择分别计量，不能把后者归因全部算给回执。

## 失败如何推动修正

| 运行 | 结果与用途 |
| --- | --- |
| attempt1 | 4 个模型回合后，夹具用超过 256 字符的原文做 API 查询触发 422；8 个模型响应留档，排除最终验收。修正核验 query 边界 |
| attempt2 | Windows preload 使用磁盘路径而非 file URL，观察子进程未启动，DSH 仍无工具回答；15 个模型响应全部排除。修正 URL，新增真实 relay 初始化和工具表预检，首轮无实际读取立即失败 |
| attempt3 | 20 轮、43 个已验证模型响应。共识、隔离与授权通过；发布／回滚返回 unknown，暴露决定后记录被隐藏的读路径缺陷，作为修复前反例保留 |
| attempt4 | 修正读取规则后，原议题、原输入、原提示复跑，全部行为检查通过。与 attempt3 使用同一协议 SHA-256 `ac43aeb6380aae6a761e9fd34f31aea09e85e69232dc043e6dcb02786fb52d29` |

所有阶段的来源、排除原因和边界见 [run-index.json](experiments/memory-harness-pilot/lifecycle/run-index.json)。最终结果附 8 个编译产物／评测文件的运行时 SHA-256。早期失败不混入最终通过率，attempt3 的真实产品反例也没有删除。

本轮 CLI 记忆测试 **25/25**、真实 PG 领域测试 **6/6**、引擎搜索／提炼测试 **5/5** 通过。contracts/application/core-api/CLI 的 build 或 typecheck、定向 ESLint 和新 runner 的语法检查通过。新增 PG 回归先复现缺少后续观察的失败，再验证未索引新记录可见、后续决定同修订切断旧讨论、撤回过滤、需求修订前移和归档排除；未修改上游 TencentDB 或 OpenViking 代码，也没有新增依赖。

下一轮优先做宿主上下文代次与恢复：压缩、裁剪、暂停恢复后应重置回执或恢复缺失来源，并对首次重复并行读取和不必要原文重读做独立对照。本轮关闭了 DSH 自动压缩，不能证明这些情形已经解决。再扩展 OpenCode／Codex 的同聊天连续性验证、启动时工具能力健康检查、生产可信确认适配，以及独立的事实／环境执行证据模型。

短期与长期的职责、留存策略和当前未完成部分见 [记忆生命周期](67-memory-lifetimes.md)。长期引擎的 L0/L1/L2 不是本产品的短期／长期分界。
