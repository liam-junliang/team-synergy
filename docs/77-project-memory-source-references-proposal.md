# 项目事实、资料索引与协作记忆

2026-11-12 讨论稿。用户已明确：先确认方案，暂不改变现有同步行为。本文件不表示已经移除开关、改变文档主存或启用现有项目的后台同步。

## 设计方向

文档、需求、任务、缺陷及测试记录是持续变化的业务对象，由原业务系统提供当前事实。项目记忆提供理解项目所需的背景、决策原因、约束和经验，并关联这些业务对象。资料索引保存足以发现对象的摘要与引用，不默认把整个业务资料库复制成另一份事实库。

“内容已进入检索存储”与“内容已进入模型上下文”是两个步骤。上下文开销还取决于检索返回量、是否重复取证以及是否按范围读取。引用式设计可以减少事实副本和过时风险；只保存 URL/ID 又不足以支持语义发现，因此仍需要简短但有意义的摘要、主题和关系。

| 层次 | 保存内容 | 读取规则 |
| --- | --- | --- |
| 业务资料 | 原文、结构化字段、当前状态、修订、权限与执行证据 | 通过现有 CLI/API/MCP 查询当前对象，按问题选字段、段落或分页 |
| 资料索引 | 类型、稳定对象 ID、用途摘要、语义主题、关联对象、已观察版本、当前读取方式 | 先帮助定位；返回前验证来源仍可见，不把旧摘要当作最新事实 |
| 协作记忆 | 为什么采用某方案、讨论结论、约束、经验、未解决分歧，以及来源关系 | 保留讨论/确认/实施证据的区别，可回溯原始会话与业务修订 |
| 账号记忆 | 个人风格、偏好及适用条件；后续经验证的通用经验 | 仅本人可见；不把项目事实复制成跨项目个人权威，也不从偏好推定操作授权 |

## Agent 的读取路径

```mermaid
flowchart LR
  Q[当前问题] --> K[少量项目背景 / 资料线索]
  K --> R[CLI / MCP 读取授权下的当前业务对象]
  R --> S[需要的字段或相关段落]
  S --> W[分析 / 执行 / 验证]
  W --> E[有依据的讨论结论或经验]
  E --> M[协作记忆与来源引用]
  M --> K
```

- 问“当前任务状态、需求内容、最新接口约定”时，以业务工具实时读取为准。
- 问“为什么这样做、之前讨论过什么、有哪些约束”时，先用协作记忆定位，再按需要读取关联来源。
- 一般概览可以使用已验证版本的短摘要；精确细节与执行前提需要核对当前资料。每次读取不必展开全部关联文档。
- 工具返回的业务正文和助手自己的复述不重新当成用户发言采集，避免检索内容在记忆中循环放大。原生 Hook 的角色、来源与消息身份过滤继续有效。

## 引用需要具备的语义

一个资料引用至少包含 `sourceKind`、项目与对象 code、短摘要、已观察修订、关联对象及读取能力标识。读取能力标识是受控工具/路由，不是让模型执行任意命令字符串。

稳定对象 ID 用于定位当前对象；不可变修订 ID 用于说明“当时依据的是哪个版本”。两者都保留。文档更新可异步更新索引，Agent 查询当前内容时不等待索引追平；删除、撤回或权限变化则先使旧引用不可用，再后台清理索引。返回旧摘要前也要做权限与有效性检查。

未来的静默同步主要是**索引与引用的自动更新**。需求或任务的业务修改仍由各自 API 与并发版本规则处理；一条讨论被记录，不自动等于需求已确认，更不等于代码已落实。

## 当前实现与后续改动范围

当前项目文档正文与修订仍在 PostgreSQL，已有 Tencent Wiki/Core 文档投影和按不可变来源分页读取的路径，尚未实施本文的统一引用层。本轮数据库隔离与原生会话采集也不会偷偷改变这条文档同步策略。

文档页目录与同步面板目前不是同一统计集合：目录聚合原生项目文档、需求文档、独立架构资料与测试资产；同步面板只统计原生 `project_documents` 的当前修订。因此截图中的 31 与 12 不能直接解释为“31 份资料只同步了 12 份”。尚未查询真实数据核实差额类型，也不应把某个投影进度当成项目记忆完整度。

后续先补齐统一资料目录与可实时读取的业务工具，再评估各类资料索引摘要、语义检索与范围读取的效果。页面可展示资料是否可发现、引用是否有效以及同步错误，不要求成员手动决定项目“是否拥有记忆”。后台服务配置与维护暂停能力仍属于运维控制。是否正式移除当前开关及切换索引策略，待用户确认方案后实施。

## 当前资料工具盘点

以下为静态代码核验的真实能力，没有为本讨论实现新的接口：

```bash
tsp docs list --project <project_code>
tsp docs search "关键词" --project <project_code>
tsp docs show <document_code>
```

这些 CLI 直接读取平台资料，不以启用记忆投影为前提。目录聚合四类来源；关键词搜索的覆盖不完全一致，原生项目文档支持正文搜索，架构资料目前只搜标题/摘要，测试附件字节不搜索。`docs show` 可导出当前内容，但没有通用的 `--revision`；架构和测试源有自己的历史读取入口。

`tsp memory document <revision_source>` / MCP `read_memory_document` 支持单篇原生项目文档分页与字面定位，不是全库正则 grep。当前 MCP 没有文档树/目录工具；也没有文档库路径 glob、跨文档 grep 或 LSP。已有 `tsp code search/context/callers/callees/impact` 针对代码快照与代码图，不等于文档库语言服务。

因此引用式方案的优先工作是统一四类资料的稳定路径、目录/元数据、glob、grep 命中位置与上下文、按范围/版本读取，再由 CLI 和 MCP 暴露同一套规则。普通 Markdown 可以先提供标题、链接和段落结构索引；真实代码的符号、引用和诊断应接对应代码服务。导出一篇文档后在本地运行 `rg`，不能称为已经支持完整远程文档库 grep。
