# 记忆的生命周期与一次性动作许可

2026-11-10 · 当前实现边界与下一步设计

这套架构已经把跨会话的项目知识、账号偏好与当前工作会话分开，但此前的会话游标只解决采集和重放，尚未构成完整的短期记忆。本轮增加短期检索回执与一次性动作许可，把读取历史、知识积累和执行授权分别管理。TencentDB Agent Memory 与 OpenViking 承担长期语义检索，TeamSynergy 与宿主共同管理生命周期。

## 四种不同的生命周期

| 内容 | 当前保存位置与职责 | 结束、失效与重用 |
| --- | --- | --- |
| 当前工作上下文 | 自带 Agent 的会话、压缩摘要、当前问题、工具结果和未决事项，由 harness 管理 | 新会话不会自动继承。尚未实现平台统一的任务工作记忆或可恢复会话摘要 |
| 采集与重试记录 | CLI SQLite 保存工作区绑定、已核对的转录路径和游标、消息摘要、原始版本见证；服务端回执保证同一事件只应用一次 | 能跨进程恢复，当前没有自动 TTL。解除绑定移除绑定记录，已投递事件见证仍保留，避免重绑重写历史 |
| 短期来源检查点 | CLI 独立 SQLite 按宿主会话保存来源编码、指纹和上下文代次，不保存正文或许可 | 2026-11-11 增加；距上次成功读取 24 小时有效，压缩／恢复时重验原文，`inspect`／`reset` 不延续旧来源寿命；开始新聊天或清除时丢弃引用 |
| 短期读取与动作状态 | MCP 内存中的检索回执，以及受控适配器内存中的一次性授权 ledger | 读取回执有 TTL 与容量；动作许可有明确到期时间和一次使用限制。进程退出后均失效 |
| 长期项目与账号知识 | PG 的来源、状态、业务修订与投影作业；Tencent 的项目检索投影；OpenViking 的本人记忆投影 | 当前长期片段没有自动到期字段。按来源、权限、撤回和修订判断是否有效，长期保留策略和物理清除仍需产品化 |

持久化的重试记录可能比一场会话活得更久，它的职责是证明“这个事件此前处理过”。它不能证明“这次还允许执行”。同样，检索到“提交信息用中文”可以影响措辞，检索到“上次让我推送”不能产生本次推送许可。

Tencent 与 OpenViking 的提炼层级、摘要层级分别服务于各自的内容组织和检索。不能把它们的 L0、L1、L2 直接对应为本产品的短期、长期或权限级别。[引擎映射设计](63-agent-memory-harness.md)

## 当前会话如何少读重复正文、又能发现变化

MCP 的 `context_receipt` 是一份有限期的读取回执。首次读取返回完整结果与一个新回执，后续模型可显式把上次回执传给检索或背景读取。回执绑定 API 实例、账号、设备凭据、工作区和项目，不保存原文，只保存来源指纹与状态。模型没有传回执时照常获得全文。

每次读取仍请求服务端的搜索或背景接口，并通过 `/sources` 重验旧回执中的来源。来源仍可访问且内容与状态不变时，返回精简的 `unchanged_sources`。同一来源发生变化时返回最新内容。撤回或不再可访问的来源只列为 `unavailable_sources`。显式展开一个来源始终返回当前全文。

默认回执 TTL 为 30 分钟，同一 MCP 进程最多保留 128 个回执，每条分支最多跟踪 40 个来源。回执不可变，新读取产生新分支，重试旧回执不会改变其基线。过期、容量淘汰或进程重启后回退为全文，并返回 `receipt_reset=expired_or_unknown`。会话所属账号或工作区变化要求重启 MCP。`TSP_MEMORY_CONTEXT_MODE=full` 用于相同工具协议下的全文基线对照。[读取实现](../apps/cli/src/memory-context.ts)

这项优化减少的是模型再次接收的正文。源重验仍有服务端开销，不能宣称减少了全部后端请求。来源已经进入模型聊天历史后，工具无法把那段旧文本从模型上下文里删除，工具必须明确报告失效，Agent 在后续回答中以新证据为准。

回执仍有效也不能证明宿主保留了先前的正文。宿主压缩、裁剪上下文或从摘要恢复后，应重置回执（首次读取省略 `context_receipt`），或对缺失正文调用 `read_memory_source`。本轮连续聊天实验关闭了 DSH 的自动压缩，只证明未压缩会话内的去重与更新。尚未接入各 harness 的压缩事件，也没有把回执绑定到宿主上下文代次，不能声称已自动解决压缩后的资料恢复。

2026-11-11 补充：已为三个记忆工具增加可选的宿主会话检查点与 `context_epoch`，并提供 DSH 原生压缩／恢复事件适配器。上段描述的是 11 月 10 日实验的边界；新的接入方式、真实压缩与重启验证、仍未接入的宿主路径见 [恢复设计与验证](69-memory-context-recovery.md)。它恢复来源引用并重新取文，不替代平台的任务状态或宿主的聊天摘要。

## 一次性推送许可如何独立于长期记忆

新增的 [memory-authorization.ts](../apps/cli/src/memory-authorization.ts) 为受控 harness 适配器提供纯内存 ledger。它处理一次向某个分支推送一个确定提交的许可，不执行 Git 命令。

1. 适配器解析并固定账号、项目、宿主会话、操作类型、仓库身份、远端身份、目标分支与完整提交哈希。
2. 当前操作者通过宿主可信确认通道批准这个具体操作。适配器调用 `confirm`，传入唯一人类确认事件 ID 和到期时间，得到不透明 `grantId`。
3. 模型执行入口只接收 `grantId`，操作目标由适配器绑定。`executeOnce` 重新计算摘要并核对范围、状态与到期时间，在调用动作回调前同步消耗许可。
4. 失败、超时和远端结果不确定时仍保持已使用。适配器先核对实际结果，确有重试需要时取得新的明确确认。同一确认事件重放只返回原许可，不能增加次数或更换目标。
5. `revoke` 撤销尚未使用的许可；`invalidateSession` 撤销指定账号、项目和会话的许可。过期、已使用、撤销、范围不符或未知令牌均在动作回调前拒绝。

操作摘要使用固定顺序的字段数组与 SHA-256，覆盖账号、项目、会话、`git_push`、仓库、远端、分支和提交。完整提交哈希固定待推送代码。仓库与远端身份由适配器规范化，远端应绑定解析后的 URL 或等效身份，仅使用可被改指向的 `origin` 名称不足以保证目标不变。执行器必须再次使用这些固定值，不得把单分支许可扩展成多分支、强推、删除或其他命令。

```ts
import { createMemoryAuthorizationLedger } from './memory-authorization.js';

const ledger = createMemoryAuthorizationLedger();
// 当前操作由适配器提供，不能取自模型传入的目标或检索结果。
const operation = {
  account: 'alice', project: 'project-a', session: 'chat-a',
  operation: 'git_push' as const,
  repo: canonicalRepoIdentity, remote: resolvedRemoteIdentity,
  branch: 'refs/heads/dev', commit: exactCommitHash,
};

// 只由宿主可信的人类确认回调调用，不能注册为模型可调用工具。
const grant = ledger.confirm({
  ...operation,
  confirmation: { id: humanConfirmationEventId, source: 'human' },
  expiresAt: Date.now() + 60_000,
});

// 模型工具只带当前许可令牌，真实执行目标固定在闭包中。
await ledger.executeOnce({ ...operation, grantId: modelInput.grantId },
  () => performExactBoundOperation(operation));
```

`source: 'human'` 表达调用方契约，无法鉴别任意调用者是否真的来自人类。宿主须把确认方法与模型工具隔离，并验证人类事件来源。ledger 默认最多保留 256 个许可及其确认事件，满额时拒绝新增，避免淘汰旧事件后重放出新许可。重启后旧令牌全部无效，宿主也不能自动把保存的人类事件当成一次新的当前确认。

本轮由多轮模型评测的 `fake_push` 接入 `executeOnce`，动作回调只记录模拟效果。未注册生产推送 CLI 或 MCP 工具，也未拦截成员自带 Agent 的任意原生 shell。成员通过其他终端直接运行 `git push` 可以绕开该 ledger。若平台需要真正控制某类动作，必须把执行入口纳入受控适配器，并单独验证宿主提供的审批能力。仅在提示词里要求模型再次询问，达不到这项保证。

## 从短期发现积累为长期知识

会话增量进入整理入口后，先区分项目讨论、账号偏好、明确采纳、当次操作请求和不清楚的内容。长期条目保留来源事件、项目或账号范围、关联对象和版本。模型分类只是候选，服务端继续核对公开资格、身份、对象绑定与修订。

- 项目设想保存为讨论证据，其他成员可查并参与。明确采纳关联原讨论与需求修订，不能把采纳直接表示为交付完成。
- 工作习惯和个人隐私只投影到本人空间，跨项目适用性需要条件。当前原生切片仍受已绑定项目对象约束，更通用的账号经验整理尚未完全实现。
- 一次性推送、删除等许可留在当前受控操作状态，不通过记忆写入路径转成长效授权。现有提取器把纯当次请求判为 `transient`，不生成长期片段。
- 实施、测试、发布、回滚各有独立证据和环境。曾经“已发布”的来源仍可作为历史被检索，当前生效状态应读取最新执行记录，不能靠删除历史来表示回滚。

业务修订、采集回执、长期来源片段与投影作业在平台事务内关联，远端索引异步更新。重试保留原来源与版本见证，不能遇到冲突后悄悄把同一消息套到新版本。读引擎命中时再解析到当前可访问的正式来源。完整转录默认留在本地，当前同步入口主要读取用户消息，助手先行问题仅用于受限的指代证据。[采集实现](../apps/cli/src/memory-capture.ts) · [整理规则](../apps/core-api/src/memory-extraction.ts) · [长期数据结构](../packages/persistence/src/schema.ts)

## 验证与下一步

一次性授权的自动化测试覆盖记忆冒充确认、账号或项目或会话及操作目标漂移、并发只执行一次、执行失败后不可重用、确认事件重放、到期、主动撤销、会话失效、进程重启与容量上限。回调计数用于证明被拒绝的请求没有执行效果。[测试](../apps/cli/tests/memory-authorization.test.mjs)

本轮实际模型对照应分别报告检索调用、全文字符数、输入输出 token、来源重验、错误状态，以及未经授权的模拟动作次数。把“模型最后答得正确”“模型选择了正确工具”“工具确实阻止了动作”分开计量。模型能否按工具设计处理同聊天变更、跨项目引用与回滚，需要真实多轮回放验证，单元测试不能代替模型效果证据。

通过本地 Magpie 调用 DeepSeek V4.1 Flash 的多轮对照产物归档到 [lifecycle 实验目录](experiments/memory-harness-pilot/lifecycle/)，汇总见 [生命周期验证](68-memory-lifecycle-validation.md)。真实模型结果待独立核验，以该报告列明的实际运行与证据为准。本页的模块边界和单元测试结论不能直接作为模型通过率。

接下来应补齐平台可见的当前工作记忆、暂停与恢复、压缩前未决事项摘要、长期来源保留与物理清除策略，以及生产 harness 的可信确认接入。短期摘要可引用长期来源与版本，在恢复时重验；长期知识也应记录最后确认时间、适用条件与替代关系。用户无需把全部聊天逐字写进引擎，Agent 在需要时主动检索有效背景，工作中的可复用发现再按来源与权限积累。
