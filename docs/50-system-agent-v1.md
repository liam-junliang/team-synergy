# 系统 Agent：批注、修改提案与规格生产

状态：方向已由项目负责人确认；V1 已实现并同步到运行服务，已完成隔离样例的真实模型与页面验证；企业级规格生产稳定性仍待后续评测。日期：2026-10-21。

## 1. 业务目标

把项目资料生产从一次性对话变成平台可重复执行的工作能力。团队通过全局对话或文档批注安排任务；平台保存输入、来源版本、执行过程、候选结果及采用记录。后续将同一能力连接到代码与补充资料的规格生产流程。

本轮实施前已具备文档版本、规则质检、项目权限、审计、规格接入候选和固定版本 Skill；本轮补齐平台内作业执行器、持久批注及候选修改的采用流程。开发任务 Run 仍服务于用户本地编程，系统 Agent 另有运行边界。

## 2. 已确认的原则

- 草稿自动：分析与候选修改可以自动执行。
- 正式资料先确认：展示具体差异、来源、风险与检查结果；用户点击采用后才能保存正式新版本。
- 平台控制权限、版本、审计和业务动作；DeepSeek Harness（DSH）承担模型执行，可替换。
- 系统 Agent 使用独立工作目录。源码仓库、service 程序目录、用户工作空间和系统 Agent 作业目录相互区分。
- 事实、推断、建议与未知分别表达。生成者给出的理由不等于独立审查结论，规则通过不等于企业验收通过。
- 模型输入中的指令不能扩大作业权限；模型没有直接写数据库、采用提案或持有用户平台令牌的能力。

## 3. V1 范围与用户流程

第一条交付闭环是**项目文档批注 → 生成修改草稿 → 查看差异 → 确认采用 → 文档新修订**。

1. 已登录用户在项目页面打开悬浮的系统 Agent 面板。
2. 选择具有编辑权限的项目文档，或在文档页面选择原文后创建批注；记录文档编号、修订、原文和修改指令。
3. 平台保存任务及文档快照。DSH 在独立目录处理快照与固定指导，自动生成结构化候选。
4. 面板显示任务状态、候选标题/摘要/正文、修改理由、来源说明、警告和确定性规则结果；用户能比较完整前后内容。
5. 用户拒绝、取消或明确采用。采用请求携带基准修订和服务端计算的候选摘要。
6. 平台在一个事务内核验权限与版本，保存不可变新修订、任务结果与审计。基准过期则拒绝覆盖，用户重新基于当前版本提出修改。

V1 的对话以当前项目、当前请求人的持久任务历史组织，一条修改指令对应一个任务。支持取消与失败后重新提交，刷新可以恢复结果。

V1 先覆盖文档库原生项目文档。需求、架构、测试资料在统一文档库中的关联视图仍有各自领域写入规则，后续逐类接入，界面应说明限制。全仓库自动逆向、多步骤研究、独立 Agent 复核、跨项目动作、定时任务和代码修改属于后续阶段，不显示为已完成能力。

## 4. 架构与运行边界

```
全局面板 / 文档批注
        ↓ 当前用户身份
Core API：项目权限 → 输入快照 → 持久任务
        ↓ 内部领取、执行令牌、租约
DSH adapter：固定版本、独立工作目录、受限执行配置
        ↓ 结构化候选（不拥有平台写权限）
Core API：校验候选 → 规则检查 → 等待用户确认
        ↓ 基准版本 + 候选摘要 + 当前授权
文档新修订 + 采用记录 + 审计
```

V1 采用模块化单体内的后台执行循环，避免引入独立队列和新的部署服务。持久数据在 PostgreSQL；应用重启后能识别失效的执行租约并明确失败，不静默重复付费推理。进程内的执行器后续可独立部署，业务接口保持稳定。

目录约定：

| 目录 | 责任 |
| --- | --- |
| `F:\workspace\team-synergy` | 源码、Skill、评测题目、判定标准与实现测试 |
| `F:\workspace\team-synergy-runtime\team-synergy-service` | 已同步的平台程序 |
| `F:\workspace\team-synergy-runtime\team-synergy-user-space` | 用户的本地编程工作空间 |
| `F:\workspace\team-synergy-runtime\team-synergy-system-agent` | 系统 Agent 独立作业临时目录与运行状态 |

运行根目录不作为模型访问整个文件系统的授权。V1 将授权文档快照注入输入，禁用模型文件、shell 等通用工具；后续代码研究增加受限的只读来源连接器。远端部署不能凭用户提供的本地路径读取其电脑。

DSH 使用经核查的固定版本，不自动追踪 latest。提供部署级启用、程序路径、模型、凭据来源、任务目录及超时设置。缺失配置应明确显示不可用，不以脚本模拟模型成功。凭据只供执行器认证，不进入文档、模型输入、API 返回或版本库。

部署入口：`scripts/start-dev.ps1` 读取 `TSP_SYSTEM_AGENT_CONFIG_FILE` 指定的 JSON；未指定时读取 service 上级目录的 `system-agent.config.json`。文件只保存允许的部署设置及凭据路径，不接受密钥明文。直接启动 Core API 时使用 `.env.example` 中列出的进程环境变量；这份示例文件不会被启动器自动加载。构建时将 Skill 指导打包到 Core API 的 dist，开发监听同样读取已构建的包。

当前限制：修改指令最多 8000 字符，引用最多 20000 字符，目标文档最多 100000 字符，标题/摘要/正文/指令/引用的 JSON 输入最多 300000 UTF-8 字节。复杂任务应拆分，超限在创建任务前拒绝。

## 5. 数据、状态与一致性

任务保存：公开编号、项目、请求人、文档编号、基准修订、基准标题/摘要/正文、批注、指令、幂等键、状态、候选、候选摘要、规则结果、执行身份与租约、错误、采用修订及时间。

主要状态：`queued → running → awaiting_review → applied/rejected`；等待或执行时可取消；超时、执行失败和失效租约显式进入 `failed`。取消或失去执行权后到达的旧结果不能改变任务。

所有用户接口重新验证项目访问权；领取、结果接收和采用还需验证请求人当前写权限。采用限制为当前请求人且仍拥有文档编辑权限。任务不产生全能机器人账号，也不扩大原始请求人的权限。

采用事务锁定任务及文档，比较修订与候选摘要。相同采用请求重试返回同一修订，不产生重复历史。普通人工修订同时补齐版本锁，避免与 Agent 采用竞争造成覆盖。修改标题和摘要也必须出现在确认界面。

## 6. 文档标准、质检与 Skill

复用 `skills/spec-production` 已有的来源、事实分类、验收与未知项准则；调用时固定实际指导内容并保留摘要。每个候选执行确定性规则检查，明确列出仍需人工或独立 Agent 核验的事项。

证据说明必须区分：输入快照可由平台验证，模型解释的推论仍需核验。V1 不宣称已经检查未提供的仓库文件、运行过测试或完成独立语义审查。

后续增加独立审查者与评测集后，再讨论按风险自动放行。企业级质量以真实覆盖、可追溯、可验收和可维护为目标，不以单一总分代替判断，也不将参考国际标准表述为获得认证。

## 7. 验收条件

| 编号 | 可观察条件 |
| --- | --- |
| SA-01 | 项目页面可打开全局入口，原生文档能选择或批注，指令和结果刷新后保留 |
| SA-02 | 真实 DSH 生成候选；执行前后正式文档修订与正文均不变 |
| SA-03 | 标题、摘要、正文的前后差异、理由、来源与检查限制可查看 |
| SA-04 | 明确采用后只增加一个修订；重复采用不重复写入；任务与审计可追溯 |
| SA-05 | 基准版本过期或候选摘要不匹配时拒绝采用，不覆盖新文档 |
| SA-06 | 只读用户、跨项目访问和撤权后的写入被拒绝；不泄漏他人私有任务输入 |
| SA-07 | 超时、取消、失效租约与异常结构化输出可恢复到明确状态，旧执行结果不能覆盖 |
| SA-08 | 未配置时显示原因；真实模型调用与测试替身的验证结果分开记录 |
| SA-09 | 模型工具被限制，工作目录与用户空间隔离，提示注入不能授予数据库/平台写权限 |
| SA-10 | 源码检查与隔离测试通过，迁移前备份，同步到 service 后实际页面与真实任务验证 |

### 当前限制与下一阶段

- 第一版每条指令对应一个任务；尚未接入需求/架构等领域文档写入、仓库文件读取、多资料检索或独立审查 Agent。
- 当前真实平台样例成功证明流程成立，不代表多项目稳定性。适配器前序合成试跑曾有一次失败，随后成功；失败记录保留，原因未完全归因，不隐藏为全程成功。
- 作业目录保留输入快照与执行日志用于追溯，尚无自动保留期限/清理策略，需由部署维护者管理；凭据未写入模型输入或输出资料。
- 停机脚本仍以受管理 PID 与进程标识匹配服务；极端 PID 复用与进程树快照期间的变化不属于本轮已证明消除的风险。
- 下一阶段优先增加受限资料查询工具与领域文档适配，再复用既有 intake/质量门禁跑“代码 + 团队资料 → 规格候选”，以多项目评测验证覆盖率、事实准确率、修改成本和复现率。
