# ADR-0016：核心时间按可验证的双写阶段迁移

- 状态：Accepted
- 日期：2026-10-23
- superseded_by: null

## 决策

先迁移 projects.created_at、tasks.created_at、audit_events.timestamp。它们是这三张表当前全部事实时间字段；其它聚合另行分批。新表采用 timestamptz，不再新建 text 时间列。

0050 仅扩展影子 timestamptz 列，旧字段名和应用读写保持不变。数据库 BEFORE 触发器从每次写入的旧字段生成类型值，回填历史值并用约束验证镜像一致。所有写入方（包括旧应用、CLI、本机 SQL）都在此边界内；直接修改影子列会重新按旧字段计算。有限 ISO 日期明确解释为 UTC 零点，完整时间要求时区，保留微秒精度；无效日历、相对时间、无限时间、无时区时间均中止迁移或拒绝写入，不猜测或删除存量。

发布 0050 后须记录测试和运行库的实际双写一致性，确认三列非空、所有旧值可转换、镜像无差异，备份可用后才编写/发布后续切换迁移。没有规定用一次迁移模拟观察期。真实用户没有新写入时如实记录，隔离数据库中的应用/SQL 写入验证单独列出。

后续迁移在短暂维护窗口取得表锁，重查镜像、切换同名类型列并移除旧列。类型字段默认 now()，保留有限时间约束和时段索引。Drizzle 使用字符串形式的 ISO UTC 适配，API 仍返回字符串而非 Date 对象；微秒部分不能被 JavaScript Date 截断。以语义等价的 UTC 规范化时间替代原始文本格式是本项明确的契约变化，业务字段、审计正文、公开编码、并发版本不变。

本次运行库规模很小，事务内建索引和回填可控；大表必须按 runbook 在离线/受控作业中分批回填、事务外 CONCURRENTLY 建索引，不能照抄在线全表更新。

## 验证要求

迁移前后行数与事实字段不变；非法存量原样保留且迁移回滚；偏移时区、微秒、跨时区日期、双写修改/新插入及 SQL 时间范围索引均覆盖。先记录展开阶段的完整回归与真实运行对账，再保留收缩前备份和收缩后证据。

测试夹具中的 t0/p0/r2 不是合法时间，改为保持同样顺序的固定 ISO 值；非法时间测试作为独立拒绝路径保留，不能让生产解析器接受占位符来维持测试。

依据：[PostgreSQL 修改表](https://www.postgresql.org/docs/16/ddl-alter.html)、[Drizzle PostgreSQL 类型](https://orm.drizzle.team/docs/column-types)。
