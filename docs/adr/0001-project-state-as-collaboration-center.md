# ADR-0001：以项目共同状态为协作中心

- 状态：Accepted
- superseded_by: null
- 日期：2026-08-12

## 背景

项目可能由不同人、不同设备和不同 Agent 工具共同参与。要求所有 Agent 共享全部上下文、思考过程和工作目录，会带来信息噪音、权限风险、文件污染和工具绑定。

## 决策

以版本化的项目共同状态作为协作中心。Agent 通过任务契约获取工作，通过独立 Task/Run 工作区执行，并通过 Proposal、Artifact 和 Evidence 显式更新项目。

项目正式状态包括：

- 已确认需求和验收标准。
- 已生效决策、术语和契约。
- Feature、Task 和依赖状态。
- 正式产物和验证证据。
- 影响协作的风险与阻塞。

Agent 的私人思考、临时文件和未发布代码不属于项目共同状态。

## 结果

正面影响：

- Agent 工具、模型和设备可以替换。
- 不同人的经验与观点得以保留。
- 项目状态可以追踪、验证和恢复。
- 工作区隔离和临时文件清理更清晰。

代价：

- 需要定义任务、产物和证据的最小 Schema。
- Agent 必须显式提交影响协作的信息。
- 平台需要维护状态版本和发布边界。

## 被否决的方案

### 共享完整 Agent 聊天记录

噪音过多，难以作为权威状态，也容易泄露个人上下文。

### 所有 Agent 共用一个项目目录

无法隔离未提交代码、临时文件、权限和执行基线。

### 以某个具体 Agent 框架为中心

会绑定工具，无法支持个人自选 Agent 和后续替换。

## 实施约束

- CLI、MCP 和 Web 必须使用同一核心 API。
- Task/Run 是工作区和身份隔离单位。
- 没有证据的“完成”不能成为验证完成。
- 不因终态设想提前引入复杂分布式组件。
