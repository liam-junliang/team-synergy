# ADR-0010：数字主键与无前缀公开编码

- 状态：Accepted
- superseded_by: null
- 日期：2026-08-17

## 背景

历史实现把 `TEAM-...`、`PROJECT-...`、`TASK-...`、UUID 和短随机串直接作为数据库主键，并允许调用方在创建部分实体时手工填写。这使数据库关联、URL、CLI 参数和界面文案混用同一个“ID”概念，编码长度与规则也随实体变化。登录账号还曾被当作用户关联键，进一步放大了身份歧义。

## 决策

持久化实体统一采用两层标识：

1. 数据库主键使用 PostgreSQL `BIGINT GENERATED ... AS IDENTITY`。实体间关联只保存数字外键，数字值不进入 URL、CLI 或界面。
2. 对外使用不可变 `code`。编码为 20 位大写 Crockford Base32，字符集为 `0-9A-HJKMNP-TV-Z`，不带 `USR-`、`TEAM-`、`PROJECT-` 等实体前缀，服务端或受信客户端从加密随机源生成，唯一索引兜底。
3. API、Web 路由和 CLI 接收、返回并展示 `code`；创建团队、项目、Feature、需求、任务、缺陷等实体时不允许用户填写编码。
4. `account` 是登录账号，名称、模块键、版本号、Revision、Snapshot 和验收标准局部编号都是独立业务字段，不套用公开编码规则。
5. 审计事件使用 `entity_type + entity_id` 定位多态实体；展示时可附带目标实体的公开编码。审计事件本身仍具有数字主键和公开编码。
6. `members`、`team_members`、`task_dependencies` 是没有独立生命周期的纯关系表，使用数字关联列组成复合主键，不额外制造无意义的实体主键或公开编码。

公开编码不承担实体类型、排序或业务分类。类型由表、API 资源路径和字段名确定；排序使用数字主键或时间字段。

## 兼容与迁移

迁移分为同一维护窗口内可验证的四步：新增数字主键和公开编码、建立旧字符串到数字主键的映射、把关联列转换为数字外键、切换应用与客户端到公开编码。旧字符串可以作为短期只读别名帮助已有脚本过渡，但不能继续生成，也不能在新界面展示。

迁移前必须备份 PostgreSQL 数据库并确认没有 `active` Run。工作区目录可以保留历史名称；数据库中的 Run/Workspace 关联以迁移后的数字主键和公开编码为准，不通过目录名反推实体。

## 结果

- 数据库关联类型一致，索引和连接不再携带可变长度业务字符串。
- 对外编码稳定、无业务语义，不会因实体改名或分类变化而变化。
- 用户无法通过创建表单或 CLI 自行制造冲突、格式漂移或带业务含义的主键。
- 日志、URL 和界面明确使用“编码”，数据库内部实现不泄露给客户端。

## 被否决方案

- 继续使用带实体前缀的字符串主键：类型可见但把存储标识与展示约定永久耦合。
- 直接使用 ULID/UUID 作为所有表主键：实现简单，但不能满足数字自增主键和数字关联的数据库约束。
- 公开数字自增主键：容易枚举，并把内部存储顺序固化为外部接口。
