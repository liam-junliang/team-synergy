# ADR-0011：项目级共享上下文与排他材料栅栏

- 状态：Accepted
- 日期：2026-10-23
- superseded_by: null

## 背景

上下文快照同时包含文档、需求、原型和仓库信息，原全局常量锁阻塞了无关项目。只改应用锁会遗漏数据库材料触发器。

## 决策

应用与材料触发器共同采用 `hashtext('project:' || project_id)::bigint` 作为事务 advisory lock 键。上下文读取用共享锁，材料修改用排他锁；project 是需要保持一致的聚合，不能把跨材料快照拆成互不协调的 document 锁。

单行移动按旧/新项目 ID 的确定顺序锁定。应用写事务必须在锁行之前取得项目栅栏；跨项目批量 SQL 必须先按项目 ID 排序取齐栅栏。行触发器是完整性兜底，不能代替多行事务的有序预锁；直接 SQL 逆序写可能被 PostgreSQL 判定死锁并中止，调用方应回滚重试。

用户关停涉及最后一名管理员的全局不变量，改为锁定 users 表资源，不新增全局 advisory 常量。

## 后果与验证

不同项目不再共享单一锁等待链，同项目快照与材料仍协调。保留乐观并发与 409；使用真实数据库验证同项目冲突、不同项目写入、100 个并发项目以及上下文漂移场景。
