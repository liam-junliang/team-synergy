# ADR-0008：项目文档作为统一执行上下文

- 状态：Accepted
- superseded_by: null
- 日期：2026-08-14

## 背景

项目页原先的“项目文档”实际只登记产物标题和 URI，无法在平台内阅读一份完整的项目说明，也不能保证 CLI Agent 执行任务时得到与项目成员相同的上下文。产物元数据适合交付物追踪，但不能承担项目目标、约束、约定和协作说明的正文载体。

## 决策

1. 每个项目维护一份规范的 Markdown 项目文档，正文以数据库中的 `project_documents` 为唯一运行时来源。
2. 项目成员均可阅读完整正文；项目 Owner 可创建和编辑。每次保存递增修订号并写入审计事件。
3. Web 项目工作台直接渲染这份完整文档，并为 Owner 提供标题和正文编辑能力。
4. CLI 在 `task claim` 和 `task run` 时，根据任务所属 Feature 解析真实项目，领取前读取同一份项目文档。
5. CLI 将完整正文写入工作区的 `.agent/project-state/project-document.md`，同时嵌入 `brief.md` 的“项目文档（执行前必读）”章节；执行器获得 `ACP_PROJECT_CODE` 和 `ACP_PROJECT_DOCUMENT_PATH`。
6. 项目产物继续由 `artifacts` 管理，表示提交物或外部资源，不再作为项目文档正文的替代物。

## 结果

- 人和 Agent 读取相同的项目上下文，避免 Web 说明与执行提示漂移。
- Agent 在工作区内获得领取时刻的完整快照，即使执行期间平台文档继续修改，也不会让一次 Run 的上下文悄然变化。
- 当前只保存最新正文和修订号；历史变化通过审计事件追踪，暂不提供逐版本正文回放。

## 被否决的方案

- 继续使用产物 URI：依赖外部可达性，且不能保证 CLI 获得完整正文。
- 只把正文拼入任务 brief：无法在项目页面独立阅读和维护，也会让项目上下文重复存储在任务中。
