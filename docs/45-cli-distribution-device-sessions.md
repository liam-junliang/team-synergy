# CLI 分发、浏览器授权与设备会话

成员入口为 Agent 集成 → Agent 接入 → 本地 CLI。

## 成员操作

1. 在 CLI 接入页选择系统，复制当前平台安装命令。脚本自动选择 x64/arm64，下载已发布包并校验 SHA-256。包包含 `tsp`、`agentd` 和 Node.js 运行时。
2. 运行 `tsp auth login --api https://platform.example.com/api`。在浏览器登录，核对终端授权码和设备名称，显式批准或拒绝。
3. 运行 `tsp auth whoami` 检查账号，再用现有工作空间和项目绑定命令接入项目。

运行任务和克隆仓库仍需要本机 Git；Codex、Claude Code 等执行器按成员自己的环境安装。分发包只捆绑平台 CLI 的运行时，不安装这些外部工具。

浏览器授权不会扩大用户的团队、项目或技能权限。申请十分钟有效，短码用于核对；轮询密钥仅在 CLI 内存中持有，成功兑换一次后失效。密码首次修改规则继续适用。`--no-browser` 支持远程终端；`--web` 可指定独立 Web 入口。

系统管理员可在「系统配置」保存 Web/API 公开地址，CLI 接入页据此生成安装和登录命令，并在配置页检查六种目标安装包是否发布。未配置时使用当前站点；API 与 Web 地址不同时，登录指引会带 `--web`。详见 [系统管理台与平台接入配置](46-system-administration.md)。

### 检查版本、升级与回退

| 命令 | 用途 |
| --- | --- |
| `tsp --version` / `agentd --version` | 查看当前程序版本 |
| `tsp version` | 查看 CLI 版本、对应系统和架构的安装包标识，以及正式发布记录的源码提交 |
| `tsp update --check` | 立即从安装时的平台检查本机安装包，输出已安装和可用的发布标识 |
| `tsp update` | 查看本次升级目标，确认后安装 |
| `tsp update --rollback` | 确认后切换回上一份安装，离线也能使用 |

交互终端通常每天最多检查一次，发现更新时在终端提示。脚本和 Agent 可以用 `--check` 获取 JSON。自动化执行升级或回退时需要显式传入 `--yes`。版本号相同而安装包摘要不同的重构建也能检测到，低版本只通过回退选择。

升级先核验下载包，再统一切换以后启动的 `tsp` 和 `agentd`。已有运行继续使用启动时的程序，用户授权、工作区和项目绑定保留。早期没有 `tsp update` 的安装可在 Agent 接入页重新执行安装脚本。源码运行的 CLI 随仓库更新。

## 设备和会话

| 对象 | 定义 | 行为 |
| --- | --- | --- |
| 客户端设备 | 某个账号下，某个 Web 浏览器配置或 CLI 安装的稳定身份 | 可重命名；重复登录不重复创建；保留任务及交接关联 |
| 登录会话 | 一次成功登录产生的访问凭据 | 独立登录时间、到期时间和吊销状态；新会话默认 90 天有效 |
| 最后登录 | 该设备最近一次成功登录的时间 | 刷新列表、轮询、调用业务 API 不会更新它 |

“设备”不等于物理电脑。同一电脑的浏览器和 CLI 分开列出，不同浏览器配置也分开；清理浏览器存储或 CLI 安装身份后需要重新授权。不采集 MAC 地址或硬件指纹。

安装身份由随机 UUID 与本机随机秘密组成。CLI 按 API 地址隔离保存，Web 保存在当前站点浏览器存储；服务端只保存秘密摘要。UUID、设备编码和名称都不能用于认证。安装身份只负责在有效登录后复用正确设备记录。

CLI 的 `auth logout` 和单会话吊销只影响该会话；同一设备的其他会话继续有效。整体吊销设备会同时撤销它的所有会话和任务租约，保留设备、Run、交接与审计历史。重新完成授权可以恢复该设备身份，但不会恢复已吊销的会话或租约。平台不能远程终止已离线的本地进程；服务端后续心跳与写操作会按授权和租约状态拒绝。

设备/会话接口只允许本人或系统管理员管理，团队/项目管理员不会因此获得他人的账号会话管理权。

## 老数据与执行兼容

迁移 `0037_device_sessions.sql` 为原设备凭据建立独立会话，保留原设备 ID、公开编码及任务执行派生密钥。迁移的旧会话沿用原有效性（不额外追加到期时间），可以从会话管理中吊销。旧记录每次登录产生一行，因此用其原登录创建时间初始化最后登录；无可信时间的记录显示未知。不会仅根据相同名称、平台或 IP 合并历史记录。

已有登录客户端通过现有有效凭据认领安装身份，不需要复制数据库密钥。旧凭据只迁移一次，退出或吊销后不能被兼容逻辑重新激活。

Run 租约和交接校验改为从当前会话找到稳定设备。用户权限、设备状态、租约状态仍实时复核；同设备重新登录可以继续原执行身份，换设备需要原有接管/交接流程。CLI 本地运行日志和交接状态改用稳定设备摘要，兼容已验证旧会话对应的本地摘要；兼容索引只保存摘要，不存历史令牌。独立 `ACP_TOKEN` 不能冒用配置文件中另一设备的执行身份。

`AGENTCTL_HOME`、`~/.agentctl/auth.json`、项目绑定、工作空间、旧 `--token` 和密码登录保持兼容。更新安装包保留用户配置及旧安装版本，运行中的进程继续使用原版本；安装脚本不替换项目代码。

如果旧版 `agentd` 正持有运行租约，服务端会保留该设备旧会话的原到期时间，并在租约结束后允许迁移。回退到 0.1 时，已启动的 0.2 工作进程继续使用原版本。新启动的 0.1 命令只能使用当前尚有效的访问令牌，自动续期需要 0.2 或更新版本。

## 构建和部署

成员无需构建；以下由平台维护者或 CI 执行：

```sh
pnpm install --frozen-lockfile
pnpm --filter @team-synergy/cli... --filter @team-synergy/agentd... build
node scripts/build-cli-distribution.mjs --platform win32 --arch x64 --source-revision "$(git rev-parse HEAD)"
```

支持 `win32`、`linux`、`darwin` 与 `x64`、`arm64`。构建器默认固定官方 Node.js `22.23.3`，从 nodejs.org 获取并核对官方 SHA-256；`--node-version` 可显式更新固定补丁版本。每次修改 CLI、agentd 或其共享依赖后必须重新打包；不能只重启 API。

默认输出 `output/cli-distribution`，用 `--out` 指定其他目录。逐目标构建会维护发布清单，清单只列出实际存在的产物。正式发布应从干净输出目录构建全部目标，并将整套产物作为一次部署发布，避免混合不同提交的安装包。

GitHub Actions 的 `Platform CLI distribution` 工作流可手工触发，或推送 `cli-v*` 标签触发。它构建六个目标并验证汇总清单，输出 `platform-cli-distribution` artifact。将解压目录挂载到 API 服务的 `ACP_CLI_DIST_DIR`（绝对路径）；开发环境默认读取仓库 `output/cli-distribution`。

Web 的 `/api` 代理须保留这些匿名下载路径：

```text
GET /cli/install.ps1
GET /cli/install.sh
GET /cli/manifest.json
GET /cli/releases/<manifest-listed-filename>
```

发布目录只存安装脚本、清单和构建包。服务端只提供清单白名单中的文件，不提供任意目录读取。未部署清单或缺少目标架构时，页面明确显示不可安装。正式平台使用 HTTPS；安装脚本仅允许本机回环地址使用 HTTP。

Windows 默认安装到 `%LOCALAPPDATA%\TeamSynergy\cli`，Unix 默认到 `${XDG_DATA_HOME:-$HOME/.local/share}/team-synergy/cli`。PowerShell 支持 `-InstallDir`、`-NoModifyPath`，shell 支持 `--install-dir`、`--no-modify-path`。非托管目录、路径链接、并发安装和校验失败会被拒绝；旧版本目录不自动清理，维护者确认没有进程使用后再清理。

## 验收要点

- 从平台 HTTP 获取脚本和包，在隔离用户目录运行 `tsp --version`、`tsp auth --help`，不依赖源码或系统 Node。
- 同安装多次授权只产生一个设备；新会话凭据不同，最后登录更新；退出当前会话不退出浏览器或其他会话。
- 覆盖未批准、拒绝、过期、过快轮询、重复兑换、跨账号管理与设备吊销。
- 旧凭据迁移不改变执行密钥；同设备重登后原租约和交接状态可用；另一设备不能冒领。
- 包摘要不符、目录不归安装器管理、未发布架构必须失败，保留旧入口与用户配置。

设计参考：[RFC 8628 设备授权流程](https://www.rfc-editor.org/rfc/rfc8628)、[uv 安装分发](https://docs.astral.sh/uv/getting-started/installation/)、[Node.js 官方发布文件](https://nodejs.org/dist/)。本平台复用设备授权的交互和限制，未将当前接口声明为通用 OAuth 服务。
