# Agent 对自然问题的主动项目检索

验证日期：2026-11-17。

## 接入方式

用户可以直接问业务问题，不需要每次追加“先查平台”“使用 MCP”或工具名。接入层仍须给模型检索能力和稳定的使用规则；本轮验证的是取消逐题提醒，不是让完全没有任何指导的模型自动知道平台。

`tsp mcp` 的初始化响应通过 `instructions` 提供通用检索规则：项目事实先取证、普通常识直接回答、项目不明确先澄清、取得足够依据就停止、引用实际来源并保留条件。工具说明补充真实查询语义；连接上下文提供当前账号与默认项目，不预装项目文档全文或测试题答案。CLI 的宿主接入说明复用同一组规则。

本机安装的 DSH 0.2.1-rc.2 会把 MCP `instructions` 注册为系统提示中的 `mcp:<serverName>` 段落，在后续模型请求中使用。工具卡只列举能力和参数约定。初始化成功不等于一定检索，也不等于答案一定正确，必须继续检查真实调用和来源。

流程为：自然问题 → 确认项目上下文 → 按问题选择资料或记忆 → 返回当前来源片段 → 据此作答。规范、需求和设计优先项目资料；近期讨论和决定使用项目记忆。正文按需从业务库读取；短索引和工具卡不能伪装成已读取的文档。

## 项目上下文

项目选择规则沿用 [账号连接与项目上下文](./80-mcp-account-project-context.md)。工具输入的 `projectCode` 优先于启动参数 `--project`，再优先于工作区绑定。

- 用户明确说出项目名：通过项目发现工具解析编码，再读取该项目。
- 用户只说“这个项目”，连接已声明默认项目：沿用默认项目。
- 没有默认项目且项目名不明确：先询问，不能通过浏览多个项目内容来猜选。

固定一个项目的宿主可使用 `tsp mcp --project <真实项目编码>`，无需本地项目目录。账号级连接可以保持无默认项目，按每个问题明确选择。启动上下文只声明身份，不包含业务问题答案，也不授予提交、推送或合并权限。

DSH 连接建立后不会仅因服务端指令文件改变而重新读取指令；更新 CLI 后需重连 MCP 或重启该宿主连接。完整替换系统提示的自定义宿主配置可能屏蔽该段落，需要另外验证。

## 实验控制

实际使用 DSH、现有本地 Magpie 配置和配置名 `workbuddy/deepseek-v4.1-flash`。未独立证明代理上游实际路由到的厂商模型身份。每例建立空白会话，工作目录为空且无父级项目绑定，问题文本不包含检索指令。模型没有本地仓库或旧聊天可直接读取。

只读实验代理转发真实已安装 CLI 的 MCP 响应与指令，记录完整 RPC，并暴露 15 个只读能力；阻止写入、私人信息访问及本地文件、Shell、联网和子 Agent 等竞争工具。此限制用于控制风险与取证，不能把结果推广为所有默认工具组合均稳定。

每例统一预算为 120 秒、8 次工具调用、6 个模型步骤，最多两例并发。预算触发可能与并行调用竞争，因此同时保留实际 RPC 数、事件尝试数与中止原因。没有通过放宽预算改善结果。七题和评估标准在对照运行前冻结，执行者不读取金标准，独立评估者不读取生产策略代码。

最初一批七次模型运行因测试代理未正确转发 SDK 的发现协商而没有可用 MCP。这批标为无效测量，成本保留，不能算作模型检索失败，也不能从统计中无声删除。修复后使用原生 MCP SDK 预检，再进行下列有效对照。

## 同题默认项目对照

额外一例保持问题“这个项目怎么提交？”、预算、工具范围和空工作目录不变，仅在 MCP 启动时声明 Team Synergy 默认项目，不并入上述七题分母。

- 无默认项目：2 次发现调用后先澄清项目。
- 有默认项目：确认 `projectSelection=startup` 后读取正确项目的现行 Git 规范，5 次调用、37.376 秒，带真实修订引用作答。

该对照通过，说明项目身份可以由接入层提供，用户不用每次重复项目名或检索指令。仍观察到已知默认项目后重复列项目、相似目录查询等开销，后续可继续减少。

## 本轮改动与边界

生产改动集中在四处：`memory.ts` 提供共享检索规则并用于接入说明；`memory-mcp.ts` 在初始化时发布规则，协议服务版本为 0.3.1；`agent-connection.ts` 的无默认项目反馈要求先澄清；`agent-capabilities.ts` 明确目录的连续子串语义、grep 默认 literal 与显式 regex 的差别，以及读取资料的三种定位方式。没有变更业务存储、项目授权或检索算法。

CLI 构建、类型检查、四文件 ESLint 和独立审查通过。相关本地 HTTP stub/临时目录回归为 38 通过、1 项真实数据库测试跳过；最终版本的 11 项连接与隔离回归全部通过。未运行数据库预置脚本。Windows x64 分发包已更新，并验证两端 HTTP 下载、全新目录安装和无登录无绑定的 MCP 初始化；其他操作系统安装包不在本轮验证范围。

保留的改进目标是：减少已知项目后的重复发现；统一旧宿主指导中“先简报”和文档优先规则的重叠；约束回答将“未确认”提升为“事实不存在”的推断；换问题、重复运行，并在完整原生工具集及其他 harness 下复测。当前没有每次回复自动二次调用模型纠错，也没有宣称检索策略能保证模型严格服从。

检索结果中的来源代码来自本机测试数据，仅用于追溯本轮记录。它们不是生产策略的硬编码。原始 RPC、冻结标准、逐例独立评估、失败运行成本和分发证明保存在 runtime 的 `dsh-natural-retrieval-20261117` 目录；不录入业务文档库。
