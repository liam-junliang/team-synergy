# 跨模块业务验收与证据矩阵

给产品负责人、研发及测试共同走查。所有人名、订单、版本号都是隔离夹具；“通过条件”规定如何裁决结果。原型能验证操作者能否找到入口、看清前后状态和恢复路径；库测试和 API 测试才能验证持久化以及拒绝后是否有副作用。各模块另有详细验收及实现引用。

| 编号 / 需求 | 前置与执行 | 通过条件及反例 |
| --- | --- | --- |
| AC-ACCESS · M02-F05、M02-F06 | Owner 预览 team_write 收紧至 team_read；成员甲继承写权、乙有显式 viewer、丙是外部 member。甲有未交接工作时先保存，再使用已交接样例重试。 | 第一次拒绝且原权限仍在；第二次只有甲降为只读。普通成员不能提交同一操作。验证入口：`packages/application/tests/permissions-policy.test.mjs:91-148`。 |
| AC-PLAN · M03-F04、M03-F05 | 项目负责人把待规划功能放进有明确起止日期的里程碑，再设置结束日越过窗口的排期。 | 允许恰好贴边；越界失败，保留之前已保存的里程碑和日期，不增加更新事件。此前只归入里程碑但缺日期的功能仍在待规划抽屉；已有完整日期的功能仍在计划上。核对计划对象和原始日期：`packages/application/src/schedule.ts:24-49`。 |
| AC-REVIEW · M04-F03、M04-F06、M04-F07、M04-F08 | 有写权成员提交讨论，管理者发布决定；补齐验收条件后由管理者推进确认，冻结选定需求修订。换到旧父基线重试。 | 决定不自动交付需求；冻结使用指定版本。过期父基线不能覆盖新基线，刷新后重新选修订。有只读角色和未消除的开放问题时分别走只读和不能确认的分支。见 M04 各功能的守卫及基线测试 `packages/application/tests/baseline-use-cases.test.mjs:36-53`、`packages/application/tests/baseline-use-cases.test.mjs:113-122`。 |
| AC-HANDOVER · M08-F07、M08-F08、M08-F09、M08-F10 | A 停止受托 Run，项目管理者发布固定包；首次恢复绑定 B 当时所用的设备，准备激活前由管理员处理来源漂移，再让 B 发新的就绪回执。 | 无停止回执不能发布，首次绑定后的其他设备不能继续恢复。任务契约漂移不能豁免；可批准的其他漂移不可直接绕过，批准后旧就绪回执不再有效；激活新 Run 与确认来源变化是不同动作。见 `packages/application/tests/handover-use-cases.test.mjs:235-260`、`packages/application/tests/handover-use-cases.test.mjs:473-504`。 |
| AC-DEFECT · M09-F04、M09-F06、M09-F08、M09-F09 | 记录一次固定用例修订的失败执行，创建缺陷并分诊、建立修复任务。在提交但未验证时尝试回归，再以已验证任务重试。 | 原结果保持 fail；pass 项不能建缺陷。未验修复阻止回归；已有 verified/closed 修复满足这一守卫。管理者决定关闭或重开，是否有新的 pass 证据需另行核实。见 `packages/application/src/defect-use-cases.ts:199-228`。 |
| AC-MEMORY · M13-F03、M13-F04、M13-F05 | 接手者检索项目规则并读指定来源；持有人检索自己的提交习惯。两个窗口编辑同一版本，另测撤回及无可见来源。 | 项目记录有范围、修订和原文入口；个人偏好不授予推送许可。冲突后先读新版本，历史与当前可检索集合可区分。不可见时提示查目录或问操作者，不显示他人私有来源。见 `packages/application/src/personal-memory-use-cases.ts:81-114`。 |
| AC-INTAKE · M10-F01、M10-F02、M10-F07、M10-F08 | 操作者在固定代码运行上采集结构和图关系；审核者退回一条无证据的候选，再冻结已裁决计划。用相同请求键重放写入。 | 原始图关系不能直接成为已批准需求；拒绝未冻结计划；成功条目不重复创建，失败项及依赖能区分。此项用协议和只读回执验收，不模拟 GUI。见 `packages/application/src/intake-use-cases.ts:376-425`。 |

**执行与签认。** QA 保存操作者角色、数据基线、输入、结果截图或回执、拒绝后的对象版本；工程负责人核对实际守卫，产品负责人决定是否采纳业务推断。首次源码审阅不能替代业务 UAT。生产环境的可用率、恢复目标、可访问性符合等级与高并发性能，需在目标环境另定标准再测试。
