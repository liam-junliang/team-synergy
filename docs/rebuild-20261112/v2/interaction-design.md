# 交互设计与原型走查指南

此稿给产品、设计、研发及 QA 在同一套情境中评审。进入项目的「设计」工作台，按下表标题选原型，打开“视觉与交互原型”及配套说明；本地可直接打开同名 HTML。每个原型针对一个决策点，数据为隔离示例，预览内操作不改变业务记录。

| 原型标题 / 本地文件 | 主角色和关键决定 | 评审者实际操作 | 验收 |
| --- | --- | --- | --- |
| 成员入项与权限变更 / access.html | 成员核对授权来源，Owner 确定收紧权限会影响谁 | 从名册切换负责人，比较“尚有未交接工作”和“已交接”两种结果，再检查两个显式例外；在计划页试试日期边界 | AC-ACCESS、AC-PLAN |
| 从议题决定到需求基线 / review.html | 提案人、项目管理者和只读者分别判断：已讨论、已确认还是已经冻结？ | 从讨论记录走到冻结；换到父版本已变化的情境，读取最新父版本再选择；检查只读视角及尚有疑问的提示 | AC-REVIEW |
| 运行交接、验证与缺陷回归 / delivery.html | 执行成员 A、接手成员 B、独立验证 Run 与管理员判断工作能否继续 | 比较无停止回执、错误设备、来源漂移与重新就绪；从失败用例追到缺陷、已验证修复以及重开或关闭 | AC-HANDOVER、AC-DEFECT |
| 记忆检索与私有修订 / knowledge.html | 接手者按权限读项目来源；账号持有人判断个人偏好是否还可用 | 在项目、本人、版本冲突和无可见来源间切换，展开原文和修订。核对“有记录”不能代替业务验收或推送授权 | AC-MEMORY |

**信息设计。** 首屏交代项目或账号范围、当前角色、正在处理的对象。成功反馈说明具体变更；受阻反馈说明原状态是否保留、缺少什么，以及谁能接着处理。确认页展示影响对象和依据版本，避免让人凭一个“确定”按钮猜后果。用标题、文字及控件状态共同传达角色和结果，颜色只作辅助。窄屏阅读时先看当前动作，再看其证据和返回入口。

**覆盖边界。** 这些稿为关键业务旅程服务。CLI 和后台处理保持命令、输入/输出或状态回执形式，例如代码理解与规格采纳使用 AC-INTAKE；不为没有界面的流程补画页面。平台实际页面仍以对应版本实现为准。原型交互验收、代码测试、真实业务验收各自留证；评审稿不会据此变更为业务已批准或已经上线。
