# 从代码理解到规格采纳：命令与状态走查

使用者是绑定仓库的规格编写者和有发布权的项目管理者。协议通过 CLI 回执与 Web 审阅操作配合。以下是状态示例；占位符由操作者替换，准备、草稿、裁决及正式写入各有自己的结果。

| 场景标识 | 操作 | 验证结果及重试 |
| --- | --- | --- |
| scope-pinned | 核对已发布代码运行的快照、目录清单和摘要；在该来源上准备候选。 | 能点回具体文件和行；工作区后来的编辑不应悄悄改变上一份依据。 |
| candidate-reviewed | 本机 `tsp intake validate <file>`，合法后提交草稿；`tsp intake preview <batch_code>` 读取证据和当前决定。 | 校验通过不创建业务实体。缺证据或关系不明时退回候选；只有实际业务裁决能改变计划。 |
| plan-frozen | 管理者在工作台核对逐项决定、依赖、质量依据后冻结；持计划摘要与请求键执行 apply。 | 版本过期或计划未冻结时拒绝；拒绝后查看实际结果再决定是否重建计划。 |
| plan-partial | 查逐项结果和业务编码。成功项保留；区分直接失败、依赖阻塞与已完成。 | 对进行中的请求以原键查询或恢复；已有终态后按平台续传条件处理。停止不是删除此前成功的业务对象。 |

验收：AC-INTAKE；模块：M10-F01、M10-F02、M10-F07、M10-F08。命令入口见 `apps/cli/src/intake.ts:1-53`；服务端写入和收据见 `packages/application/src/intake-use-cases.ts:376-425`。本轮公开的是项目文档、架构和原型；没有用这份协议向业务工作台批量创建或批准结构化需求。
