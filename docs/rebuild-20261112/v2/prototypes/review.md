# 订单导出评审原型说明

[打开可点击原型](review.html)。示例围绕一次客户对账：运营发现导出只包含当前页，负责人需要留下替代决定，研发要知道本期按哪一份验收标准交付。原型使用预置订单、成员和修订编号，无网络、无业务写入；刷新后可从入口重演。

## 角色、数据与界面边界

- **周宁，项目负责人。** 处理新反馈、发布替代决定、确认需求和冻结基线。选择新父基线时仍要重新确认范围。
- **陈清，有写权限的项目成员。** 能反馈并更新本人对指定需求文档修订的意见。投票完成后由管理者独立选择评审结论。
- **只读项目成员。** 能查设计依据、决策和基线中固定的验收标准，操作区提示只读身份。
- **对象样例。** T-17 为议题，DEC-01/02 为先后决定，P-06 R2 为设计原型，D-04 R2 为进行中评审所绑的文档，最新文档为 R3。REQ-12 R3 是结构化需求，V2、V3、V4 是基线。在正常夹具中 V3 属于本次冻结；在冲突夹具中 V3 已由其他人创建，本次成功恢复后得到 V4。不同夹具通过导航显式切换。
- **交互设计范围。** 当前产品已支持这些业务对象、角色和规则。本原型将议题、确认需求和冻结基线串成一个用于审阅的工作区。基线冻结当前有服务接口，旧 Web 基线地址会转到需求文档；整套逐屏布局属于本次交互设计。依据 `apps/web/src/workspaceRouting.ts:48-55`、`apps/core-api/src/routes/baselines.ts:11-50`。

## 逐屏操作与观察结果

“评审流程”可进入关键步骤，“其他场景”可独立查看文档评审、只读、空数据和并发冲突。表中的定位符是页内状态 ID，可在独立 HTML 中打开同名片段。

| 屏幕、角色 | 可核对的字段和材料 | 操作与结果 | 功能追溯 |
| --- | --- | --- | --- |
| #topic，周宁 | T-17、问题、来源想法 I-08、运营反馈、旧决定 DEC-01；展开可见 P-06 R2 与 D-04 R2 | “处理反馈并形成决定”进入处置；另一入口可独立查评审 | M04-F02、M04-F03、M05-F01、M06-F03 |
| #decision，周宁 | 决定正文、替代理由、被替代记录、处置选项 | 未选时不能发布。选“暂缓”返回已重新打开的议题；选“记录新决定”后出现记录入口 | M04-F03 |
| #decided，周宁 | 已决定、DEC-02、保留的 DEC-01、来源文档 | 核对回执，进入结构化需求 | M04-F03、M04-F06 |
| #requirement，周宁 | REQ-12 R3、关联文档、AC-01/AC-02、未决问题数；可展开原型和文档依据 | “确认”进入已确认；也可切换到含未决问题的独立夹具 | M04-F06、M04-F07、M05-F01 |
| #questions，周宁 | 尚有一个未决问题及原因，状态保持澄清中 | 载入已解决的示例后才能演练确认 | M04-F07 |
| #confirmed，周宁 | 已确认、正文修订、验收编号、来源 | 进入基线选择；确认需求本身不会生成基线 | M04-F07、M04-F08 |
| #baseline，周宁 | 名称、范围、冻结原因、预期父基线 V2、可选需求/修订/状态 | 勾选 REQ-12 R3 后才出现冻结按钮。可单独演练他人先冻结 | M04-F08 |
| #frozen，周宁 | V3、父级 V2、选定 R3 的验收标准 | 展开后续 R4 对照，冻结内容仍保留 43 条样本 | M04-F08、M04-F09 |
| #conflict，周宁 | 预期 V2 与实际 V3、待选修订、未产生新基线 | 重新载入最新父级 | M04-F08 |
| #rebased，周宁 | V3 的名称、待冻结 R3、范围和原因 | 核对后明确再次确认，进入 V4 回执 | M04-F08 |
| #frozen-v4，周宁 | V4、父级 V3、需求 R3、原验收编号 | 查看恢复后的实际父子关系 | M04-F08、M04-F09 |
| #review，陈清 | D-04 指定 R2、最新 R3、成员意见、文本质检与待人工核验范围 | 展开版本差异；把本人在 R2 评审的意见更新为“支持” | M04-F05、M06-F04 |
| #voted，陈清 | 两位成员各一条当前意见、绑定 R2、评审依然开放 | 返回结构化需求；无需等待文档评审闭合 | M04-F05、M04-F06 |
| #readonly，只读成员 | DEC-02、P-06 R2、REQ-12 R3 和 V3 | 展开验收标准；无法发布决定、修订或冻结。切换负责人示例属于演示导航 | M04-F09、M05-F01、M06-F03 |
| #empty，周宁 | 可选修订数 0、现有需求为草稿、入选资格 | 无冻结入口，可进入独立确认示例 | M04-F07、M04-F08 |

## 可重演验收

每个用例可重新打开 HTML 取得初始视图，或按表中入口切换对应预置夹具。浏览器内的这些结果是原型交互验证；表后另列业务实现及现有测试定义。

| 验收 ID | 前提与动作 | 预期并观察的结果 |
| --- | --- | --- |
| RV-AC01 | 从 T-17 展开原型/文档出处，进入处置，先不选，再用键盘选“记录新决定” | 未选时无发布入口；选择后可记录 DEC-02，回执保留被替代的 DEC-01 |
| RV-AC02 | 从已决定页选择 REQ-12 R3，核对两条 AC，确认，再进入基线 | 先见“已确认”回执，再见单独的基线申请；空选择不能冻结 |
| RV-AC03 | 勾选 REQ-12 R3，冻结，展开后续变更对照 | V3 指向 V2，基线记录 R3 的 43 条；示例最新需求 R4 不改变基线内容 |
| RV-AC04 | 从“父基线已更新”进入冲突，点击重新载入并核对 V3，再确认 | 首次冲突不产生新基线；恢复后得 V4，父级为其他负责人先建的 V3 |
| RV-AC05 | 打开文档版本评审，查看 R2/R3 差异，将陈清意见改为支持 | R2 的评审中仍只有陈清和周宁各一票，状态仍为评审中 |
| RV-AC06 | 分别进入只读、空数据、未决问题场景 | 可读固定验收但无冻结按钮；0 个符合条件的修订没有提交入口；有未决问题时需求保持澄清中 |
| RV-AC07 | 仅用键盘聚焦详情并按 Enter、聚焦单选按 Space；在窄屏重复主流程 | 详情可收展；状态随选择变化，焦点可见；375px 视口无横向溢出 |

业务实现和测试定义可回查：议题及撤回 `packages/application/src/requirement-collaboration-use-cases.ts:321-350`、`packages/application/tests/requirement-collaboration-use-cases.test.mjs:29-82`；同版投票 `packages/application/src/requirement-collaboration-use-cases.ts:465-497`、`packages/application/tests/requirement-collaboration-use-cases.test.mjs:140-164`；需求和基线 `packages/application/src/requirement-use-cases.ts:752-771`、`packages/application/src/baseline-use-cases.ts:169-199`、`packages/application/tests/baseline-use-cases.test.mjs:98-125`。本说明没有执行这些业务套件。

## 实测环境与兼容处理

2026-11-12 使用本地 Playwright 与 Chromium headless，读取本原型 HTML。在独立文件 1200px、375px（关闭脚本），以及以 data 文档装载的 sandbox 375px（关闭脚本）均完成演示。另从固定源码读取工作台注入的完整 CSP，在本机拦截的 HTTP 宿主中构造 srcdoc，分别用 sandbox="allow-scripts"（1200px、375px）及 sandbox=""（375px）复测。六组均实点完成 15 个状态、正常冻结、冲突恢复、投票、只读/空/未决场景；键盘 Enter 展开资料，Space 选择单选项，最终宽度检查未出现横向溢出。未连接运行中的产品数据库，也没有对业务系统创建任何决定或基线。

普通文件使用片段导航。工作台的 srcdoc 会从宿主继承相对 URL 基准，普通片段会指向宿主页；原型检测工作台注入的 CSP meta，在该环境仅展示 `about:srcdoc#状态名` 链接。单选、复选、详情和隔离文档中的定位均使用浏览器原生能力。若另一个宿主自行构造 srcdoc，应沿用相同 CSP 标记，或将本 HTML 作为独立文件/data 文档载入。依据 `apps/web/src/DesignWorkbench.tsx:216-219`、`apps/web/src/DesignWorkbench.tsx:351-355`。
