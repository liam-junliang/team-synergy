# TeamSynergy 项目背景

## 服务谁，为什么需要这个平台

一个软件团队的产品、研发、测试和负责人会围绕同一件事持续工作。有人提出想法，有人把它变成需求，有人写代码，也有人接手缺陷和验收。成员使用自己的 Agent 和工作环境。换一个人、换一个工具或开一个新会话时，团队仍希望答得出三件事：为什么做、改动影响谁、怎样知道已经做好。

## 团队希望怎样工作

平台承载共同项目的背景、规划、讨论、决策、交付记录和证据。成员可以从正在讨论的问题出发，也可以从一项明确的任务出发。Agent 应能在需要时找到资料、读到指定版本的原文、了解上下游，在信息不足时向操作者提问。一次讨论会产生设想；确认方案需要相应的决策依据；宣称已经落实还需要实现或验证依据。

成员的一般经验、行为偏好和私密信息归账号。特定项目的需求、业务规则、缺陷和接口约束有各自的适用范围。过去的工作习惯可以指导表达和协作，提交、推送等具体动作仍取决于当前授权。交接时，接手的人需要能判断每条信息的出处、范围、状态和时效。

## 给源码分析者的问题

沿着一条真实的业务路径，从界面或命令追到权限和状态判断、持久化、异步工作及可观测的结果。分别记录哪一步由谁发起、哪个对象持有事实、何时算成功，以及另一位成员接手时可以核验什么。指出产品目标与当前实现之间仍缺哪些环节。

以上是本轮分析的产品意图，作者为本次任务的主 Agent，依据为项目操作者对目标的描述。具体角色权限、状态转换、存储与检索行为，以及外部引擎能力，均需在本次源码快照中重新取证。
