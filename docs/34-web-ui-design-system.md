# Web UI 设计与实现规范

## 1. 适用范围与执行方式

本规范面向设计、开发和执行任务的 Agent，适用于正式应用 `apps/web` 的项目首页、需求、计划、设计、任务、文档、交接和缺陷工作台。
沿用现有 slate / cyan 协作工作台：清晰的信息层级、可读的内容、稳定的操作位置。不要引入营销落地页式的大标题、装饰渐变或巨型空白。
下文是新增和修改界面的目标标准，不代表旧页面已经全部符合；遇到旧页面差异时按本规范收敛，不复制遗留写法。
共享样式入口是 [`apps/web/src/index.css`](../apps/web/src/index.css)，操作层级细则见 [Web 操作控件风格标准](29-web-ui-action-style.md)。

## 2. 字号、字重与行高

| 内容角色 | 字号 / 行高 | 字重 | 使用约束 |
| --- | --- | --- | --- |
| 页面标题 | 24 / 32px | 600–700 | 每个工作台一个主标题 |
| 弹窗标题 | 20 / 28px | 600 | 与标题下说明分层 |
| 区块标题 | 16 / 24px | 600 | 用于独立内容区，不把所有卡片抬升为大标题 |
| 列表、卡片标题 | 14 / 20px | 600 | 长标题允许换行，保持可扫描 |
| 正文、文档内容 | 14 / 22–24px | 400 | 主要信息不得降为辅助字号 |
| 标准输入值 | 14 / 20px | 400 | 普通输入框、下拉框、文本域一致 |
| 工具栏紧凑输入值 | 12 / 16px | 400 | 仅搜索、筛选，与同行按钮对齐 |
| 表单标签 | 12 / 20px | 600 | 标签与输入值分开设置字重 |
| 按钮、局部分段选择 | 12 / 16px | 500 | 标准与紧凑按钮保持同字号 |
| 辅助说明、校验提示 | 12 / 20px | 400 | 说明用途、约束或错误的恢复方式 |
| 编码、时间等元数据 | 至少 11 / 16px | 400–500 | 只用于次要信息，不承载主操作或业务规则 |

- 全局导航使用 14px；局部分段选择使用 12px。不要通过全大写、小字号和加大字距替代中文标题层级。
- 主要内容不使用 8 / 9 / 10px。数据较多时优先缩减重复说明、调整排版或提供局部滚动。
- 禁止用 `!important` 或 `!text-*` 修补字体冲突；定位共享样式、级联层和组件语义后修正。
- 不新增无级联层的 `button, input, select, textarea { font: inherit; }`；Tailwind base 已处理基础继承，控件类明确声明字号、字重和行高。

## 3. 颜色与状态

| 用途 | 基准 | 规则 |
| --- | --- | --- |
| 页面与卡片 | `slate-50` / 白色 | 以留白、边框区分区域；避免层层重阴影 |
| 主标题、正文 | `slate-900` / `slate-700` | 正文优先保证可读性 |
| 辅助文字 | `slate-500` | 白底说明不依赖更浅的 `slate-400` |
| 主操作、选中强调 | `cyan-700` | 同一操作区只有一个主操作 |
| 普通边框 | `slate-200` / `slate-300` | 输入边界应可辨识 |
| 成功、待处理、错误 | emerald / amber / rose | 必须同时给出文字或图标含义 |

- `slate-400` 可用于禁用或装饰，不作为白底可阅读信息的默认色；深色导航按背景单独检查对比。
- 选中状态同时使用浅背景、边框或下划线及语义属性，不能仅改变文字颜色。
- 加载、空、失败、无权限和禁用是不同状态，分别解释原因；可恢复的错误提供重试或下一步。

## 4. 控件与交互层级

| 控件 | 尺寸目标 | 共享入口 |
| --- | --- | --- |
| 标准按钮 | 高 32px，圆角 8px | `ui-button` + 语义变体 |
| 紧凑按钮 | 高 28px，圆角 8px | `ui-button-compact` |
| 局部辅助动作 | 高 28px，圆角 8px，无重阴影 | `ui-context-action` + 语义变体 |
| 图标按钮 | 32 × 32px，圆角 8px | `ui-icon-button` |
| 分段选择 | 选项高至少 28px，12 / 16px、500；外壳圆角 8px、内嵌选项 6px | `ui-segmented` / `ui-segmented-item` |
| 标准表单 | 最小高度 40px，14 / 20px，圆角 8px | `form-control` |
| 工具栏紧凑表单 | 最小高度 32px，12 / 16px，圆角 8px | `form-control-compact` |

- 新增控件优先复用共享类；不要在每个组件中重新拼接一套字号、高度、圆角和焦点样式。
- 主操作用于推荐下一步；取消、编辑和下载通常使用次要操作；危险操作显式写明对象与后果。
- HTML、图片、URL 链接、特殊文件四种资料类型使用同一组分段选择；选项是 `type="button"`，用 `aria-pressed` 标记当前项。
- 分段选择改变当前局部视图或表单类型，不使用 `submit`，不冒充页面导航；页面导航使用链接和 `aria-current`。
- 图标按钮必须有可辨识名称；仅装饰的图标隐藏于辅助技术。移动端增加周围留白，避免紧凑按钮紧挨造成误触。

## 5. 表单与键盘

- 标签必须关联输入控件；placeholder 只做示例，不能替代标签。必填、单位和限制靠近对应字段。
- 输入字号和字重由控件类明确控制，不继承外层粗体标签；同一表单的文字输入和下拉选择使用相同基准，工具栏搜索和筛选才使用紧凑例外。
- `focus-visible` 提供清晰 cyan 焦点环；Tab 顺序跟随阅读顺序；按钮支持 Enter / Space。
- 错误同时提供文字和边界反馈，通过 `aria-invalid` 与 `aria-describedby` 关联；不能只显示红边。
- 禁用有明确视觉差异，必要时说明条件；保存期间显示进行中状态并防止重复提交。
- 上传失败保留已填内容；切换资料类型不得让未完成读取覆盖当前选择；文件类型与大小限制在选择前可见。
- 长说明使用多行文本域；不要为了压缩高度把正文做成单行输入。紧凑表单仅用于工具栏搜索和筛选，正文编辑器不得使用 `form-control-compact`。

## 6. 间距、容器与长内容

- 使用 4px 基准，常用间距 8 / 12 / 16 / 24 / 32px；同类内容保持同一密度。
- 控件圆角 8px；卡片 12–16px；弹窗 16px。分段选择内部选项采用 6px 圆角适配 8px 外壳，除此之外不临时引入另一套控件圆角。
- 卡片内边距通常 16px，页面和主要弹窗内容区通常 24px；小屏可降至 12–16px。
- 标题、状态和主操作排列稳定；信息较多时让工具栏换行，不压缩控件字号或截掉操作。
- 长标题允许换行；编码、URL、文件名使用可断行容器或明确复制入口。截断时必须能打开或查看完整内容。
- 列表、代码、表格和原型画布可独立滚动；外层容器设置可收缩宽度，避免把整个页面撑出横向滚动。
- 文档正文保留舒适阅读宽度；不得把长段落堆进狭窄元数据栏。

### 6.1 文档阅读器与资料列表的滚动约定

- 承担滚动的视口本身不设置顶部内边距；视觉留白放入内部内容容器。阅读器头部采用 `sticky; top: 0`，吸顶边缘与实际滚动视口顶端对齐，不能留下正文露出的缝隙。
- 头部使用不透明背景、分隔边框与足够的层级，防止正文从头部上方或背景中透出；滚动期间保留标题、摘要、版本信息与操作，不为吸顶隐藏阅读上下文。DOC、API、DIAGRAM 及需求文档阅读器统一复用 `DocumentReaderHeader`，需求文档继续保留分享、编辑、提炼、评审与历史记录入口。
- 测量阅读头部的实际高度，通过继承的 `--document-reader-header-height` 同步目录吸顶偏移和正文锚点的 `scroll-margin-top`；目录链接复用 Markdown 的滚动、焦点与历史记录处理。长标题换行、窗口变窄或切换语言后重新适配，不用固定像素猜测头部高度，避免目录或定位后的正文被遮挡。
- 头部与实际滚动容器之间不得插入带 `overflow-hidden` 或 `overflow-auto` 的包装层，以免改变吸顶参照。仅需裁剪圆角时可使用 `overflow-clip`，不要额外建立滚动容器。
- 桌面双栏布局中，左侧资料列表按可用视口高度吸顶，标题、搜索和筛选区固定，只有列表项区域在内部滚动；条目区设置 `min-height: 0`，确保最后一项可达。资料列表复用 `document-library-sidebar` 共享样式，需求页面左侧列表也遵循该规则。
- 窄屏改为上下排列，取消侧栏吸顶；保持搜索与列表可达，避免侧栏覆盖正文或占满整个阅读视口。
- 验收覆盖滚动起点、中段和末尾，并使用长标题、长篇 Markdown、高图片及 Mermaid 图表；确认头部无透出或缝隙、侧栏末项可达、正文不遮挡操作，且窄屏没有意外的页面横向溢出。

## 7. 响应式与弹窗

- 至少检查桌面、732px 小屏与 375px 移动视口；这些是验收尺寸，不要求新增相同数值的 CSS 断点。
- 小屏将主内容优先放置，侧栏移到上下排列或可切换区域；导航可局部横向滚动并保留当前项提示。
- 弹窗固定头部和操作脚部，中间内容区滚动；容器使用 `min-height: 0`、可用视口高度上限，保证提交按钮可达。
- 弹窗标题 20 / 28px、圆角 16px；小屏收窄外边距和内边距，不能依赖固定的桌面最小宽度。
- 弹窗有可访问名称；打开后焦点进入弹窗，关闭后回到触发控件；焦点不可进入背景，Escape 关闭行为保持一致。
- 图片保持比例；HTML 画布保持沙箱隔离；URL 保留原站入口；特殊文件展示名称、大小及下载操作，不尝试运行。

## 9. 当前修正范围与遗留项

- 共享 CSS 已将正文设为 14 / 24px，基础样式与组件样式分别放入 Tailwind base / components 层；移除重复字体重置，统一按钮、局部动作、分段选择及标准/紧凑表单尺寸。
- 设计资料的四类型选择与内容视图复用分段控件；原 8 / 9 / 10px 元数据提高到 11px，辅助文字收敛到 slate-500，说明编辑使用 14 / 24px；关联需求采用统一标签与元数据样式。
- 设计资料编辑弹窗采用 16px 圆角、视口限高、固定头脚与中部滚动；上传入口增加焦点环，小屏降低编辑区最小高度并允许底部操作换行。
- 任务筛选移除整组后代的强制字号覆盖；人员选择明确紧凑 32px / 12px 与标准 40px / 14px。计划时间尺度复用分段控件，项目首页/文档/缺陷采用共享标签，缺陷筛选采用紧凑表单，需求导航保留 14px 并支持横向滚动。
- 本轮 Web 测试 89 项通过（含 4 项编译 CSS 级联回归），build / typecheck 通过；lint 为 0 错误、60 条警告。浏览器访问权限被拒绝，视觉、焦点和 732px / 375px 实际交互尚未完成浏览器验证。
- 尚未对所有旧工作台完成逐项验收；遗留小字号、浅色元数据、硬编码间距和弹窗细节应在后续触及对应区域时收敛，不能把旧值作为规范例外。
- 本规范不要求重画上传的 HTML 或图片内容；平台外壳和资料展示操作遵循本规范，用户素材保持原样。

## 10. 验收检查清单

- [ ] 标题、正文、标签、输入值、辅助文字符合字号表；主要信息没有 8 / 9 / 10px。
- [ ] 共享按钮、分段选择和表单类可复用；没有新增字体 `!important` 或无层级字体重置。
- [ ] 颜色配合文字表达状态；白底正文和说明清楚可读，选中项有可访问状态。
- [ ] 主操作唯一；标签和错误关联输入；键盘可聚焦、选择、提交并关闭弹窗。
- [ ] 732px 与 375px 下无页面级意外溢出；长标题、编码、URL、文件名不遮挡操作。
- [ ] 弹窗头脚可见，中间可滚动；保存、失败、禁用、空状态提供明确反馈。
- [ ] 四种设计资料的选择、预览、说明编辑和历史下载语义一致，文件与权限行为保持正确。
- [ ] 代码检查通过，并按实际条件记录浏览器视觉与键盘验证；无法实测的项目明确标注，不以源码检查代替。
