# codebase-graph-prd-rules 对 TeamSynergy 的试跑评估

日期：2026-11-09。

**结论：这套 Skill 适合补到现有代码理解之后，负责提炼业务规则和测试设计。** 本次已经实际执行 Graphify 建图及两套 Skill 的文档流程。产物能把资格、排序、异常和逐项恢复写得比架构概要更具体；独立源码复核仍不可省略。它整理的是已实现行为，未来产品目标、优先级和批准后的需求仍需另行确定。

## 怎么跑的

- 项目基线固定为 `92728fbec04cfa34fee4421cb0a9319d1b755164`，与前面的 UA/codegraph 试验保持一致；快照含 660 个文件。
- 使用 Skill 仓库提交 `98d6a7222b3bdce3c2fbdd78bfa818b4ed2d50aa`，分别执行 `codebase-graph-business-rules`、`codebase-graph-module-rules`。
- 使用 Graphify `0.9.104`，源码提交 `6c8002eca4acad58db6160eabcb466e61fc35afb`；隔离 Python 环境运行，包含 SQL 语法支持。
- Graphify 以 `--code-only`、`GRAPHIFY_BACKEND=none` 工作，没有使用额外语义模型凭据。当前 Agent 按 Skill 读取图谱线索，再回查源码并写出文档。
- 全项目版按 13 个业务模块归组；专项选择与平台后续改造最相关的“代码/资料→规格候选→审阅→固定计划→受控写入”。
- 业务源码和运行平台没有修改；没有创建、审阅或发布平台需求，也没有调用真实数据库、任务、模型或外部业务接口。

固定提交不包含后来尚未提交的 UA/codegraph/原生阅读器接入。因此本次适合比较文档方法，不能将产物当作当前工作区所有改动的最新说明。

| 原材料完整性 | 快照的 660 个原文件字节未改变 | 试验没有改变被分析代码。 |

独立抽查修正的三个例子：

1. **质量依据变化**：不是任何报告字段变化都要重新审阅。停止操作会更新报告的批次修订，指纹特意排除此信息字段；正文、决定、规则等实质依据才需要区别处理。见 INT-018。
2. **停止已完成批次**：已 applied 的批次直接返回，不会因为存在成功项而改成 partial。见 INT-028。
3. **撤权后的异常清理**：只有本次已捕获的尝试才进入错误清理。若入口权限检查先失败，已有 running 记录不会被该请求自动清理。见 INT-030。

这些是机械的“文件存在/行号有效”检查发现不了的问题。最终稿和对应建议用例已同步修正。

## 这次产物比较有价值的地方

**把恢复语义写具体。** 专项不仅给出发布流程，还说明候选先后、同类型记录 ID 排序、父项失败后的 blocked、单项保存点与已成功项保留，以及旧幂等键重放和新键续传的区别。对应 INT-019–INT-030。

**能暴露产品预期与实现之间的差异。** 全项目稿明确区分：需求基线使用所选历史正文与采集时的标题/状态；原型修订省略需求列表时清空关联；不同文档类型不共享同一种并发协议；Verifier Run/Profile 不等于已强制不同自然人。它们是待业务确认的现状，不是本次提出后就自动生效的新需求。

**规则可以接到测试设计。** 每条规则携带条件、结果、例外、来源和测试断言；专项提供带前置数据、操作、观察点和优先级的 26 条用例，便于后续转成测试工作项。

**能识别旧说明的例外。** README 概括普通 CLI 走 API；源码还存在服务器本机只读巡检直接打开数据库的命令。产物保留这一例外，而不是仅复述说明文档。

## 使用成本与局限

- Skill 没有锁定 Graphify 安装来源、发行版本和查询输出契约。本次额外核实了官方项目与 Python 分发名 `graphifyy`；若要长期接入，需补工具版本/能力探测。
- `--budget` 不是硬上限：一次设置约 4,800 token 的种子查询，仍返回约 35,028 token 的全部边。直接交给 Agent 可能消耗过多上下文，平台适配层应限制节点、边和总字节，并显式说明截断。
- 图谱跳过 94 个非代码输入，12 个文件未分类，并报告 43 个代码输入没有符号。542 个实际快照文件出现在图的位点字段中；另外 7 种来源值是模块名或 dist 引用，不能当作可直接引用的源码文件。图谱覆盖不能等同业务覆盖。
- 全项目稿是约 94 KB 的首轮核心规则基线。适合分模块审阅，仍需补漏和按真实业务取舍收敛；没有穷尽每个分支、配置组合或部署场景。
- 这是一次实际项目试跑与定性比较，没有做相同模型、提示词、预算下的严格 A/B 实验，也没有测量 token 节约率或业务准确率。

## 和现有 UA、codegraph 怎么互补

| 能力 | 现有 UA/codegraph 接入 | 本次 Skill 产物 |
| --- | --- | --- |
| 整体理解 | UA 的系统组成、业务关系、交互地图 | 按模块组织目标、角色、输入输出和规则正文 |
| 代码定位 | codegraph 的符号、调用/影响上下文；CLI 可查询 | Graphify 做前置导航，规则最终落到源码、SQL 和配置 |
| 规则细节 | 图谱/摘要可帮助定位，规则深度取决于分析 | 提示词强制区分资格、排序、限额、并发、回滚和例外 |
| 测试交付 | 现有证据和测试领域仍负责执行事实 | 生成可转成测试工作的用例设计，保持未执行标记 |
| 版本与协作 | 平台已有项目权限、快照、运行和版本视图 | 本次是隔离文件产物；没有自动接入平台版本或审阅流程 |

**建议采用方式：** 保留已接入的 UA 整体地图和 codegraph Agent 查询，在“从代码生成需求”步骤引入这套 Skill 的文档契约、证据等级和测试矩阵。Graphify 暂作为可比较的前置适配器；是否长期增加第三套图谱工具，应由覆盖、准确性与运行成本的后续对照决定。本次未修改平台实现。
