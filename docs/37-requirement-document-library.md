# 需求文档与文档库

需求文档统一出现在文档库固定的「需求文档」目录。需求工作台继续直接阅读和编辑正文，复用共享 Markdown 渲染器，不需要跳到文档库查看。

## 同一份资料，两个阅读入口

- 需求页保留模块、关键词、关联需求、评审和修订操作；创建后自动收录到文档库，修订后两边显示相同版本。
- 文档库的「需求文档」目录直接展示当前正文、摘要和历史内容，具有编辑权限的成员可通过「在需求页编辑」进入需求页维护。
- 「项目规范」「需求文档」「架构设计」是三个独立系统目录；均不可重命名、移动、归档，也不能新建或移入子目录。
- 需求目录由需求页维护，不接收普通文档。规范目录仍可管理文档；普通目录继续支持子目录组织。

## 数据与接口

`requirement_documents` 和 `requirement_document_revisions` 继续作为需求文档与正文版本的唯一来源，原编码、关联需求、评审、任务引用及历史保持不变。文档库按项目把需求文档映射到 `system_role=requirements` 的目录，不复制正文到 `project_documents`。

`GET /projects/:code/handoff` 汇总普通项目文档、需求文档和架构设计；条目通过 `source_kind` 区分 `project`、`requirement` 与 `architecture`。原来未返回此字段的响应按普通项目文档处理。需求条目保留原 `document_code`，`GET /handoff-documents/:code` 复用需求详情权限检查并适配为文档库的阅读结构。需求条目的类型是 `doc`，界面显示 `DOC`，业务来源由目录表达。

需求条目的 `can_edit=false` 表示不走通用文档修订接口，`source_can_edit` 表示是否允许在需求入口编辑。通用文档接口拒绝向需求目录写入或通过需求编码修订；原需求写入接口、权限和审计继续生效。

需求历史原本只保存正文、摘要、关键词及变更说明，没有独立历史标题；文档库历史正文使用原 Revision，标题沿用当前需求文档标题，不推断历史标题。项目首页的说明/指引绑定候选仅包含普通项目文档。

## 初始化与升级

迁移 `0031_requirement_documents_folder` 为已有项目建立需求系统目录。原来同名的普通根目录保留原编码、内容和子目录，仅改名为「需求文档（原目录 编码）」，不会被当成需求资料。迁移不修改需求文档、版本和评审记录。

新项目初始化固定目录；兼容旧数据的读取/创建入口通过幂等初始化补齐，保证每个项目每类系统目录只有一个。

## Agent 与 CLI

`tsp docs list/search/show` 可查阅需求目录和原需求正文；创建、修订仍通过 `requirement-doc` 命令。Agent 的需求资料继续走原需求索引及任务关联文档通道，通用交接资料收集排除需求投影，避免重复装入上下文。固定交接快照保留原有需求文档 Revision 引用。

类型与系统目录的统一规则见[统一文档库与系统目录](39-unified-document-library.md)。
