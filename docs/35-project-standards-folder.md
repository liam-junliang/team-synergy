# 项目规范目录

## 使用方式

每个项目的文档库都有一个固定的「项目规范」根目录。目录通过 `system_role=standards` 标识，每个项目只有一个；名称、位置和活动状态固定，不能通过文档库操作改名、移动或归档。

规范文档默认直接存放在该目录中。系统目录不再允许创建或移入子目录；升级前已有的子目录和内容保留，项目首页继续显示活动目录分支内的活动文档，按标题和文档编码稳定排序。首页仅展示标题、简短摘要、版本和阅读入口；完整正文、编辑和历史版本仍由文档库管理。

从首页新增规范会进入文档库的创建表单，并预选固定目录。现有文档可在文档库中修改所属文件夹：移入后出现在首页，移出或归档后不再作为项目规范。归档子目录会同时排除该分支下的规范。

项目说明和参与指引继续独立引用各自的文档。

## API 与 Agent

- `GET /projects/:code/home` 返回 `standards_folder_code` 和 `standards` 数组；每个条目包含文档编码、标题、摘要、正文、Revision 和更新时间。
- 文档库文件夹条目返回 `system_role` 与 `can_create_folder`；系统根目录的 `can_edit` 为 `false`，系统目录及已有后代的 `can_create_folder` 为 `false`。规范目录仍可创建和移入文档。
- 首页 `PUT` 只接受项目说明和参与指引的关联。旧 `standards_document_code` 写入会返回明确错误，规范归属统一通过目录维护。
- CLI 上下文列出所有规范和对应 Revision；同一文档承担多个角色时复用正文副本。CLI 仍能读取旧服务返回的单份规范形态。
- 冻结交接保存全部规范的正文、角色和版本。目录移动、归档或文档归属变化会触发上下文变化检查，旧交接内容保持不变。

## 迁移

迁移 `0030_project_standards_folder.sql` 为已有项目建立固定目录，将原 `standards_document_id` 明确关联的文档移入，并清空旧关联字段。文档编号、正文、Revision 和历史版本不变。

若已有同名普通根目录，会保留该目录及内容，并明确更名为「项目规范（原目录 CODE）」；不会仅凭同名把其中的资料升级为项目必读规范。新项目或缺少固定目录的项目，在经过成员鉴权的首页或文档库读取时幂等补齐目录。

目录归属写入受上下文材料锁保护，与交接准备及激活串行，避免读取到变化中的规范集合。

三个系统目录的统一约束及兼容规则见[统一文档库与系统目录](39-unified-document-library.md)。
