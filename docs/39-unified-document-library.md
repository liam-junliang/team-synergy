# 统一文档库与系统目录

文档库统一收录项目文档、需求文档、架构设计和测试资料。各业务页保留维护入口，文档库提供共享阅读和版本浏览。

## 系统目录

文档库的顶层固定一个「项目资料」系统根，系统子目录都挂在它下面；普通目录在系统根之外自由组织。

| 固定目录 | 层级 | 内容来源 | 文档维护 |
| --- | --- | --- | --- |
| 项目资料 | 系统根 | 仅承载系统子目录 | 自动初始化，不可编辑 |
| 项目说明 | 项目资料下 | `project_documents` | 项目首页的说明/指引，文档库可修订 |
| 项目规范 | 项目资料下 | `project_documents` | 在文档库创建、修订，项目首页自动汇总 |
| 需求文档 | 项目资料下 | `requirement_documents` | 在需求页创建、评审与修订 |
| 架构设计 | 项目资料下 | `architecture_documents` | 在项目架构页或文档库的共享架构编辑器维护 |
| 测试资料 | 项目资料下 | `test_assets` | 在测试页或文档库的共享测试资料编辑器维护 |

每个项目只有一个「项目资料」根，根下每种系统目录各一个，固定为活动目录，不能删除、归档、改名、移动或建普通子目录。普通目录只能建在系统根之外，允许自由嵌套。项目首页只能绑定「项目说明」目录中的有效文档。前端操作入口、目标目录选项与服务端写入校验采用相同规则；普通目录仍允许组织子目录。

项目规范允许直接创建和移入普通文档；需求、架构、测试目录只归集对应业务资料，不接收普通文档。已有规范子目录不会被删除或打散，其文档与首页、Agent 必读规范的关联继续有效。已有普通子目录可改名、归档或移出系统目录，移出后不能再移回系统目录。

## 类型、来源与格式

| 维度 | 取值 | 用途 |
| --- | --- | --- |
| 文档类型 `kind` | `doc`、`api`、`diagram` | 界面统一显示 DOC、API、DIAGRAM |
| 来源 `source_kind` | `project`、`requirement`、`architecture`、`testing` | 决定读取、写入权限和原始版本来源 |
| 架构图源格式 `content_kind` | `mermaid`、`drawio`、`image` | 决定架构编辑器与预览方式 |

需求条目显示 DOC，架构条目显示 DIAGRAM；不再把“需求文档”作为类型徽标。普通 DOC、API 和 DIAGRAM 文档均可维护 Markdown 正文，其中 Mermaid 代码块由共享阅读器渲染；独立架构图源仍通过架构编辑器或 `tsp architecture` 保存。

旧 `general`、`integration`、`deployment`、`data`、`operations`、`release` 在读取时统一归为 DOC，旧 `api` 仍为 API。原数据库用途值保持不变，响应中的 `legacy_kind` 保留旧分类信息。旧 API/CLI 类型输入继续兼容；只修改标题或正文时保留原分类，显式切换类型才修改类型。新建默认 DOC。

## 同一来源与历史版本

文档库列表将各类原记录汇总为索引，不把需求、架构或测试正文复制到 `project_documents`。文档编码、Revision 编码、版本号、作者、时间及正文/图源都沿用原记录。

`GET /handoff-documents/:code` 对架构返回 `source_kind: architecture`、`kind: diagram`、`architecture_document`（完整架构详情与历史），通用 `content` 为说明 Markdown。历史条目的标题、摘要、说明对应原版本。共享阅读器根据选中版本同时切换图源、预览和说明，并可下载该版本图源。

架构条目的 `can_edit=false` 表示不能通过通用 Markdown 修订接口写入；`source_can_edit` 表示原架构编辑权限。架构编辑器继续提交 `base_revision`，使用原权限检查、并发冲突检测和审计。保存后同步失效两个入口的缓存。

CLI 的 `docs list/search/show` 可发现并读取架构资料，JSON 保留完整图源与版本。图源导入、修订和历史源文件导出使用 `architecture create/revise/show`。任务领取的通用交接正文通道排除需求和架构投影，避免重复收录需求或仅拿到架构说明；架构继续由 Agent 按需显式读取。

## 升级与数据保留

迁移 `0040` 为现有项目创建「项目资料」系统根和「项目说明」子目录，把既有「项目规范 / 需求文档 / 架构设计 / 测试资料」挂到根下，并把项目首页已绑定的说明/指引文档移入「项目说明」。同名普通根目录改为「项目资料（原目录 CODE）」或「项目说明（原目录 CODE）」，保留编号、后代和文档，不自动把它当作系统目录。

迁移 `0033` 扩展系统目录约束，为现有项目添加「架构设计」目录；新项目和缺失目录的旧项目通过幂等初始化补齐。已有同名普通根目录改为「架构设计（原目录 CODE）」，保留编号、后代和文档，不自动把它当作架构资料。

迁移不更新或删除三类文档正文、图源及版本，不重写旧类型，不新造文档 Revision。既有子目录完整保留。通过迁移前后的原始记录比较验证内容与历史未变。

## 测试资料归集

迁移 `0035` 为已有项目补齐固定「测试资料」目录，新项目通过同一目录初始化逻辑创建。普通同名目录保留编号和内容，并改为「测试资料（原目录 CODE）」避免混淆。系统目录仍不能删除、移动、改名、归档或创建子目录。

测试条目的 `source_kind` 为 `testing`、展示类型为 `doc`；`purpose` 区分说明、脚本、数据、环境和报告，`storage_kind` 区分 Markdown、文件、URL 和 Git 引用。它们独立于文档的 doc/api/diagram 分类。结构化测试用例和执行结果在测试工作台管理，不转成普通文档。

`GET /handoff-documents/:code` 返回 `testing_asset` 完整详情和原始版本；通用 `content` 为该版本的 Markdown 说明。共享测试阅读器负责源文件预览、下载、Git 引用和版本切换，资料作者及项目管理者按有效写权限修订。`can_edit=false` 禁止通过普通文档修订接口覆盖测试源，`source_can_edit` 表示源资料编辑权限。列表不返回文件字节，任务上下文仅提供按需检索指引。
